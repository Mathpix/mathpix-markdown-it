# PR: List rendering robustness fixes

Status: Implemented
Owner: @OlgaRedozubova
Base: master
Version: 3.1.0

---

## Context

Several unrelated inputs made LaTeX `itemize`/`enumerate` lists render incorrectly. The fixes touch the list-env, tabular and footnote block rules, the marker-width helpers (`common/display-width.ts`), and the marker-padding CSS. They ship together.

## Goal

Fix the reported list defects — clipped markers, empty `<>` item bodies, shifted `Figure N`, a swallowed list after a paragraph, content dropped from the tabular-cell export — without changing HTML for input that already rendered correctly. Marker indent must scale with the container `font-size`, and malformed input must not degrade quadratically.

## Non-Goals

- **Text between `\begin{itemize}` and the first `\item` stays a direct child of the list.** LaTeX rejects text there (`Something's wrong--perhaps a missing \item`), so there is no item to attach it to; keeping it visible is deliberate and its placement is out of scope — what to aim for is a sibling before the list, since `<ul>` admits only `<li>`. Unchanged from `master` for plain text, except that `\itemsep`/`\itemindent` now arrive whole instead of being split into an item. A `table`/`figure` float in that position is a different case and is fixed (12): LaTeX accepts a float before the first item, it contributing no horizontal material to the list. Text after the outermost closer on the same line (`\end{itemize}\end{itemize} trailing`) is dropped for a related reason: the walk has already flushed its items when that tail arrives, and a block rule cannot hand a line's remainder to the next rule. Both unchanged from `master`.
- **Two cell-export quirks stay as they are.** A `|` inside math is exported as `\|`, and a table parser does not unescape it inside the math (measured: the content reads back as `a\|b`), so the LaTeX changes meaning — unavoidable in this format, since an unescaped `|` would split the cell. A list exported from a cell ends with a `<br>`, because the separator closes every item: `| 1. a<br>2. b<br> |`. Both are pinned by fixtures.
- **Diagnostics go to the global `console`, and a degraded render leaves no programmatic signal.** A failing list rule warns once per cause per render and does not apply, so the caller gets HTML instead of an exception but cannot tell from the return value that anything was skipped. There is no channel for it: `ParseErrorList` (`md-block-rule/parse-error.ts`) is written by the tabular path and never read or exported, and `ParserErrors` is an enum of display modes for math errors. Both a public diagnostics surface and an injectable logger are library-wide API changes (117 `console` calls across 44 files, against 118 on `master`), left to one change of their own.
- **Malformed input with no blank lines is still super-linear**, whichever env is unclosed: every terminator probe is now cheap, but `newTheoremBlock` and markdown-it's `lheading` still scan forward from each block start without terminating, running the whole terminator chain per line. At 400 units that is 9.2M block-rule calls against 23k with those two disabled — the same input, linear. Each is quadratic on its own, so disabling one does not help; neither is touched here, and the shape reaches them with no list involved. A blank line between blocks avoids it.
- **Two wrapper shapes are out of scope.** A spaced `\begin {center}` in a list body does not build its wrapper — the shared open regex admits no space there — but the list renders whole (two items, nothing leaked), identical to `master`, so this is a missing wrapper rather than a broken list, and widening a constant shared with other rules is a change of its own. A wrapper env written *inside* a `tabular` cell in a list body loses the table: `\begin{tabular}{l}\begin{center} x \end{center} \\\end{tabular}` between two items renders the cell content as a bare `center` div with no table around it, on `master` and here alike, whether the inner env sits on one line or three. The list itself is no longer collateral — `master` prints the whole list as literal LaTeX for the one-line form, where this branch keeps both items — but the frame is still dropped, and restoring it belongs to how cells are parsed, not to the list scanner. `pdflatex` rejects that input too (`Not allowed in LR mode`: a `center` needs a `p{}` column or a `\parbox`), so it ranks below the valid shapes.
- **Two limits of the opacity guard, both measured as `master`'s behaviour.** A fenced code block between a wrapper's `\begin` and its closer makes the guard decline, since the closer sweep is fence-blind and a closer past a fence opener cannot be trusted: `\begin{center}` holding a fence and an `\item` renders as on `master` — three items, the wrapper printed as text — where the same shape without the fence gets two items and its wrapper. Counting fences in pairs would tell a closer inside a closed block from one after it, and is left to its own change. A single-line nested `tabular` inside a `tabular` cell keeps the opaque stack open, because the nested-tabular branch returns before the same-line close: `x & \begin{tabular}{l}y\end{tabular} \\` inside a list body prints the list as literal LaTeX on `master` and here alike. Two places decide "did it close on this line", and only one of them was taught to.
- **The speculative-parse isolation has boundaries, documented where they live in the code.** Two are visible to a consumer: the `env` rollback compares values by identity, so a key whose object a rule mutated in place is left as the parse left it (`common/env-transient.ts`); and it diffs the whole `env`, so its cost follows the size of the object the consumer passes — 62 ms against 164 ms with 1000 extra keys on the same 200 units. The rest are internal: which module-global registries are restored and why the others are not, and why the inline registry pops by token kind while the block path pops by identity.

## Current Behavior

Marker width is `String.length` over `text` tokens, so wide, math and wrapped markers are undercounted and clip; padding is `px` and only on the outermost list. A speculative list parse leaks `env` flags and caption counters. `\footnote` scans swallow a following list. Inline content sitting directly in a `\begin{tabular}` cell never reaches `table-markdown`/`tsv`/`csv`. `\itemsep` is mistaken for `\item`.

## Desired Behavior

1. **Block-content items get marker padding.** Marker width was measured on the inline item path only, so a list whose long-marker items all hold a block env (`\begin{figure}`, `\begin{tabular}`, a code fence) lost its `padding-inline-start`. The width calc is now shared and applied on the block path too.
2. **Marker width accounts for wide/math/wrapped content.** Was `String.length` over `text` tokens only: East-Asian Wide/Fullwidth (`\item[11．]`), math (`\item[$x^4+x^4$]`, via rendered `widthEx`) and wrapped markers (`\item[\textbf{…}]`, via their children) are now measured instead of undercounted.

   What the estimate does not promise, by design: it reserves per glyph *class* against a Helvetica/Arial-like font, not per exact glyph, so a non-ASCII glyph can be off within a bounded margin; the Wide set is a fixed snapshot of Unicode, so a code point a later version declares Wide under-reserves by 25% until it is added (a build-time Unicode table was rejected for an estimate that is approximate anyway); math is measured only under SVG output, since `widthEx` is filled there alone — reading the LaTeX source instead tracks rendered width in the wrong direction (`$\displaystyle\sum_{i=1}^{n}$` is ~28 characters against ~3em); an image marker reserves by its alt text; and the em arithmetic assumes one `font-size` down the chain plus the shipped stylesheet's `2.5em` per ancestor, so a per-level size or a consumer rendering without that stylesheet shifts the reserve by the ratio. Above the `20em` clamp, and for a textless item followed by a wider-marker sublist, markers can overlap — the latter reproduces LaTeX.
3. **No state leak from a speculative list parse.** The rule parses into a buffered state before committing; a silent probe or abort discards the tokens.

   Transient `env` flags are restored on **every** exit, commit included — a leaked `isBlock` produced empty `<>` items on the next block. Everything else goes back only when the tokens are discarded: every `env` key the parse changed or added, diffed against a snapshot so a rule the list code never heard of is covered too; the module-global figure/table counters (a figure in a list is `Figure 1`, was `Figure 3`); and the list-level stack, pushed and popped so no half-open level closes an extra `<li>` later.

   A rule that throws does not apply — it answers "no list" and warns once per cause per render. Both paths guard themselves: the block rule for markdown-it's paragraph chain and `lheading`, the inline rule for its own call into the same engine, so whether the environment sits on its own line no longer decides between a rendered document and a failed one. Only a failure past the commit point propagates, its tokens being already in the stream; the levels and counters unwind either way.
4. **Footnote scans stop at a list start.** `\footnote`/`\footnotetext` now terminate their forward scan at `\begin{itemize|enumerate}`, so a list right after a paragraph (no blank line) is no longer swallowed as literal text. An unclosed env short-circuits twice: before parsing when the source holds no closer at all, and during the body walk when the closers left ahead are fewer than the envs already open. Probe answers are deliberately **not** memoized — with those two checks in place a memo measured slower on every shape, and its key would have to enumerate every input the answer depends on to stay correct. The second check is what covers a document that does end with a valid list — the sweep over-counts closers (one inside a fence is not real), so it can only keep the walk going, never cut a list that would have closed. Input that interleaves real closers with unclosed envs is only improved, not fixed: the closers ahead outnumber the open envs, so the walk continues even though none of them will close it (measured `N^1.7` with every tenth unit closed and `N^1.9` with every other one, against `N^2.0` on `master`).
5. **Marker padding in `em`, not `px`.** The indent and the `0.625em` marker gap now scale with the container `font-size`. A custom `padding-inline-start` is emitted only when the marker overflows the default (`2.5em`), attributed per nesting level and clamped at `20em`; the attribute carries its unit (`"4.23em"`).
6. **`\item` detection requires a real command.** `\itemsep`/`\itemindent` and the bare word "item" no longer split an item or break a multiline `\footnote` inside one; item detection anchors on `\item` + a command boundary.
7. **Markdown lists indent `2.5em`, not the UA `40px`.** Core-markdown `<ul>`/`<ol>` (no `.itemize`/`.enumerate`) get a scoped `#preview-content`/`#setText` rule that scales with the container; the numbered footnotes list is covered. Wrapped output only. `2.5em` equals the UA default only at a 16px base, and `PreviewStyle` sets `#preview { font-size: 17px }`, so in the shipped wrapper such a list sits at `42.5px` per level.

   A TOC under `#toc_container` or `.table-of-contents` is zeroed twice — this rule set at specificity `(2,0,1)`, and `padding: 0` from `TocStyle` later in order. A TOC copied into any other container matches no TOC rule at all, because `TocStyle` applies its parameter to the outer selectors only and hardcodes the inner ones; that shifts such a list by `2.5px` per level. Left alone deliberately: pairing every inner selector with the caller's name would also drop `list-style`, item padding, title sizes and link colours onto containers that never had them. The workaround is in the changelog.
8. **Inline content in a tabular cell reaches the export.** Content sitting directly in a `\begin{tabular}` cell was rendered to HTML only, its `table-markdown`/`tsv`/`csv` text dropped: measured, a link swallowed the rest of its cell (`[a](http://u) tail` exported as `| [a](http://u) |`) and a single-line nested list lost its sublist bodies (`| • a&#160;&#160;– <br> |`, the `b` gone). Both reach those exports now; HTML is unchanged. A flat one-line list was never affected — that shape exports the same on `master`.
9. **A link in a tabular cell keeps its label and closes its anchor.** Pre-existing and unrelated to lists, fixed here because it shares the cell-export path: the link consumed two tokens too many (open `<a>`, following content absorbed), and its Markdown label was read from one token, so a formatted label came out empty. The label is now read whole — every character that can end or re-cut a label is escaped in text and raw markup (`]` closes it, `[` re-pairs with that closing bracket, `\` escapes whatever follows), while math and an image alt pass through verbatim because both are source slices that already carry their own escapes (`image.ts` never parses the alt), math taking the cell delimiters, `$…$` by default for display math too, because a backslash added there would change the LaTeX (`\\` is a line break); those delimiters are also what shields an unbalanced `]` inside math, for any reader that has a math rule — an href that a bare destination cannot hold takes the `<…>` form — and the pptx-smoothed output no longer carries a bare `<a>` or the raw HTML of a table written inside a label. What the export cannot restore is an escape the parser already consumed: `[a\*b\*c]` reaches us as the text `a*b*c` (markdown-it's `escape` rule appends to the pending buffer, leaving no token to read), so it exports unescaped — as on `master`.
10. **Unclosed `\begin{tabular}` short-circuits.** Like fix 4, `BeginTabular` checks for a closing `\end{tabular}` before scanning to EOF instead of rejecting only afterwards, which cuts the cost of such a document by ~30×. Not list-related; included because the same probe-per-line pattern reaches it from the same malformed input.
11. **A line can carry several env transitions.** `\begin`/`\end` on one line are handled in source order, all of them: a collapsed `\end{itemize}\end{itemize}` closes two levels, and a closer mid-line can open a sibling list rather than only a nested one. Before, one transition per line was handled and the rest became item text — where `ItemsAddToPrev` drops a pure closer — so the outer list never closed and the strict no-partial-tokens bail dropped it as literal text. Source order also stops a second sublist on one line from being lost, at the cost of a whitespace-only text node between `<ul>` and `<li>` that no longer appears. A sibling opens only when the closers ahead cover what its tail leaves open — counted, not merely looked for, so a tail opening two levels needs two: an unclosed sibling aborts the rule and would take the finished list with it. Closers past the next fence opener do not count, the sweep being fence-blind. It also reports its own depth: the outermost list having closed, `parentType` is put back, or `applyListCloseState` leaving it set would make the sibling read as nested and cost it one default indent. Termination is by construction — every match consumes at least `\end{itemize}`, so the tail strictly shrinks. Text before a transition opens its own item when it carries a marker, as it already did before a wrapper `\begin`: appended to the item above instead, `\item b \end{itemize}` landed in a chunk that also held a block env, where only the first marker is read and this one printed as literal text — `pdflatex` renders that input, so the second item is owed.
12. **A block env in a list body reaches the block rules wherever it sits.** `finalizeListItems` block-parses an item only when its content holds a block env **and** an `\item`, so a chunk carrying one but no marker — the env following a closed nested list, or preceding the first item — fell to the inline path: `\begin{table}` leaked as text, `\captionsetup` left a stray `}`, and the caption was dropped. Such a chunk is now block-parsed into the already-open item, no new item token, gated by the same `LATEX_BLOCK_ENV_OPEN_RE` as the marker case — the two paths agree by construction. Measured: `table`, `figure`, `center`, `left` and `right` lost their wrapper in both markerless positions, and a `tabular` there rendered without the `table_tabular` wrapper it has at top level *and* after an `\item`, so those two positions were the odd ones out; one fixture pinned that, and it is updated. Backtick and tilde fences stay on the inline path — they are matched by the neighbouring conditions, not by this regex, and block-parsing them printed the backticks and lost the code. Both shapes are valid input — `pdflatex` accepts them with no warning — so this is a correctness fix, not tolerance for malformed LaTeX. 
13. **A wrapper env is opaque to the list scanner.** The body walk reads `\item` and `\end{itemize}` textually, with no notion of being inside a command argument, so a list command written inside a `table`/`figure`/`center`/`left`/`right` was taken as structure. Measured, with two items expected: `\caption{\item[a]}` gave **no items at all** (the bogus marker consumed the list), a stray `\end{itemize}` in a caption closed the list after one, and an `\item` inside `\begin{center}` produced three. Those five envs now join `tabular` and `lstlisting` on the opaque stack — their lines are collected raw until their own closer, so the interior is text and the block parse builds the wrapper from it. A nested `\end{tabular}` inside a `table` is content, not a closer, because the stack top picks its own pattern. The input is invalid LaTeX (`pdflatex`: `Argument of \caption@ydblarg has an extra }`, no PDF), so the aim is well-formed degradation, not fidelity — the command stays visible as caption text.

    Opening is guarded: a wrapper becomes opaque only when its `\end` exists ahead, since otherwise the stack never pops and the rest of the list, which renders today, would be collected as raw text. That decline path is pinned by its own fixture, and it is the one case a mutation of this code does not fail — by construction it equals the previous behaviour. Ahead is not enough on its own: the nearest `\end{X}` may belong to a *later* `\begin{X}`, and reaching it swallows the list's own closer, so the guard weighs what it passes. Order decides it, not a tally: with one closer and one opener in the window the counts balance, yet a closer standing **first** is still ours — measured, tallying them cost item `b` of `\begin{itemize}\item a \begin{center} \end{itemize} \begin{itemize}\item b \end{center}\end{itemize}`, where `master` renders both. One merge walk over the two ascending offset lists answers it and stops at that closer instead of classifying every transition in the window. What separates a closer that ends the list from one written as text is **brace depth, not column**: `\item b \end{itemize}` closes the list at depth 0, while `\caption{x \end{itemize} y}` carries the same characters inside an argument at depth 1. Counting line-initial commands instead was measured wrong in both directions — it kept the `\caption{}` shape rendering but printed three others as literal LaTeX, `\item b \end{itemize}` among them, which is a plain shape and one this rule set claims to support. Argument spans come from `findEndMarker`, the helper the caption and text rules already use, so escaped braces and inline code are its business rather than a second copy of that logic here — with the code-span index computed once per window and passed in, since building it per call put that helper at 21% of a parse on a document of unclosed wrappers. The window itself is bounded at 4096 characters: an unclosed wrapper reaches the document's end, and parsing that per wrapper is quadratic; past the bound a closer reads as unmatched, which declines. An unmatched `{` makes the spans unknowable — depth after it never returns to zero, and a hand-rolled counter took every later closer for argument text, opening the wrapper onto the list's own closer: measured, an unclosed `\caption{x`, a bare `{`, and `$\frac{1}{2$` (ordinary in OCR output) each printed the whole list as literal LaTeX. When the pairing fails, every closer in the window counts instead, which is `master`'s behaviour for those shapes. A closer inside a code fence does not count either. The wrapper names, their closer patterns and their cache keys all derive from one list in `consts.ts`, and the guard looks for the first *wrapper* on a line rather than the first block env — asking for the latter left the answer to where `tabular` sits among those names.

    A wrapper that opens **and** closes on one line is read on that line: pushing the opaque stack and handing the whole remainder to the item left the stack open for good, and the strict bail printed the list as LaTeX. Measured against `master`, the one shape this changes for a consumer is a single-line `\begin{tabular}{l}q\end{tabular}` in a list body, which `master` drops the whole list for; the five env wrappers reached the opaque stack only in this branch (fix 13), so their one-line form was broken and fixed inside it and comes out as on `master`. The tail after the closer goes back to the line walk, so a marker or a closer following it is read normally.

14. **A list inside a wrapper env keeps its nesting depth.** Wrapper content is collected raw and reaches the block rules from the *inline* phase, on a synthetic state that cannot see the enclosing list — so a list parsed there claims top level. The renderer reset its depth on that claim, which gave the nested list a level-1 marker and left the counter negative for the item after it. Measured, against `•  –  •` without a wrapper: any of the five wrappers between two `itemize` levels gave `•  •  •`, and for `enumerate`, where the marker is the list style, `decimal | decimal` instead of `decimal | lower-alpha`. Both branches now reset only when no list is open, and the per-render reset — depths and enumerate counters together — lives in one place, called from `reset_mmd_global_state`. The reset is load-bearing drift recovery, not decoration: gating it without that per-render call fails 8 tests.

15. **Marker macros are parsed once per document, and the source sweeps are cached where the probe can reach them.** Both are pre-existing costs this branch made visible. Every list open re-parsed the itemize marker macros (`\textbullet`, `\textendash`, `\textasteriskcentered`, `\textperiodcentered`) through the inline parser — 12 to 16 times per list block, about 250 of the ~310 inline characters a block spends. They are parsed once per macro per parse now, cached on `env` and keyed by the macro itself, so a `\renewcommand` mid-document still switches markers; the bucket is dropped when the md instance or its `outMath` changes, `env` being the consumer's and able to reach two of either, and each read hands back a copy of the array, which keeps a consumer's damage inside its own list — measured, a rule clearing the array it was handed poisons every later list without the copy and only its own with it. The tokens stay shared, so writing to one still leaks: freezing them was tried and rejected, since the library writes to none but a consumer's strict-mode renderer would then throw. The copy costs nothing measurable in time (its sign flips between runs of a same-process A/B) and ~0.7% of peak heap; `forDocx` keeps its own uncached tokens, parsing there with a mutated `outMath` and no math cache. The sweep cache had the same shape of defect for a different reason: it lived on the state object, while block rules ask through a buffered probe (`Object.create(state)`) whose own properties die with it, so the sweep reran per probe — 200 units with a wrapper in every list ran 1001 sweeps over the full source (18.1 M characters, quadratic) where 6 suffice. It is hosted on `env` now, which the probe inherits by reference, with one entry per `src`. Eviction is by age with a hit refreshing its slot: dropping the oldest alone threw out the outer document's entry — the one asked over and over — as soon as nine nested sources had passed, and its sweep count then grew with the wrapper count (5, 6, 8, 13 over 10 to 80 wrappers) instead of staying at 4.

16. **`findEndMarker` reads an escape by parity, not by the previous character.** The helper that pairs `{`/`}` for the caption and text rules treated any preceding `\` as a shield without asking whether that `\` was itself escaped, and `\\` is a line break in LaTeX. Measured: `{a\\}` reported no match where the `}` closes, `{a\\{b}` reported a match where nothing closes, and `{a\\{b}}` closed on the inner brace. End to end, `pdflatex` renders both of these and this library dropped them: `\caption{first line \\}` produced no caption at all, `\section{title \\}` no heading, and `\caption{a \\{b} c}` lost everything after the inner brace. Pre-existing on `master`, fixed here because the list guard pairs arguments through the same helper. Its optional `inlineCodePositions` parameter is new for that caller: the code-span index is rebuilt per call otherwise.

## Breaking change / migration

The list a consumer needs is in `doc/changelog.md` under **Breaking changes**; it is the canonical one and this section does not repeat it. The classes are: the rewritten marker-width model and its `em` attribute value, so custom-marker layout shifts in both directions; the scoped `ul`/`ol` indent and the specificity floor it raises to `(1,0,1)`; HTML details a diffing consumer sees (marker text now trimmed, the last `<li>` in a cell now closed, a bare `\item` in a cell now literal text); the cell exports (`table-markdown`/`tsv`/`csv` for one-line lists, link labels, math delimiters); internal `env` keys left present with value `undefined`; deep-import renames; and a failing list rule degrading instead of throwing.

Migration, in the order it bites: readers of `data-padding-inline-start` must parse an em value with its unit; anyone importing `lib/styles/styles-code` alone must also emit `MathpixStyle` for code text to keep its size; a TOC copied into a container other than `#toc_container` needs its own `padding: 0`.

## Testing

Rendered HTML is locked by full-HTML fixtures, so a visual regression fails a fixture: `_data/_lists` (marker padding per class, B2 nesting in all written forms, collapsed closers and sibling lists including the two shapes where the sibling guard must decline, a block env after a nested list, in the list fixtures and the tabular ones, a list command written inside a wrapper env, each wrapper opening and closing on one line, a closer that ends its line — with a foreign env following it, with a lone `\end{center}` below, and with neither — a marker before such a closer, crossed env boundaries where the closer and opener counts in the window are equal, an unmatched `{` in a wrapper, empty-`<>`, `\item` detection, footnote terminators), `_data/_captions` (numbering not shifted by a speculative parse), `_data/_footnotes_latex` (a `\footnotetext` mentioning "item").

Non-renderable behaviour stays as targeted assertions: `_list-marker-padding.js` (width invariant against the bundled Arial fixture, the default-indent threshold, irregular depth sequences, the `20em` clamp, malformed nesting degrading without breaking the document, padding-style sanitisation), `_display-width.js` (`isWideChar`/`textReserveEm`/`tokenMarkerWidth`, including the Unicode range edges and their Neutral neighbours), `_footnotes_latex.js` (repeated units parse linearly, with and without a valid list following them), `_parse-isolation.js` (a silent probe leaves `env` unchanged over 19 bodies, the snapshot pool, the identity boundary of the rollback, a failing rule does not fail the document on either path, diagnostics reset per render), `_tabular.js` (link labels, math syntax following `outMath.table_markdown`, `tsv`/`csv` carrying the address once, a gate on unreviewed inline rules), `_lists.js` (what counts as `\item`, no orphan `<br>` from a swallowed command; the guard table pins the exact item count `master` renders for each shape, a `> 0` assertion having passed while an item was lost, the wrapper-guard decline shapes — with and without a blank line before the foreign env, and a closer sharing the line with `\end{itemize}` — marker depth through each of the five wrappers for `itemize` and `enumerate`, markers following a `\renewcommand` that switches them mid-document and back, a math marker — the token state most likely to be rewritten — coming out alike in every list and again on the next render, and one `env` shared by two md instances keeping their markers apart), `_src-pos-cache.js` (the two boundary searches, that a sweep run inside a buffered probe is reused afterwards, that entries for different sources coexist, and that the outer document's entry survives more nested sources than the cap), `_parse-isolation.js` (render depth reset before the partial-render bail, checked by forcing drift through a no-op close rule), `_find-end-marker.js` (twelve brace shapes over the parity rule — the four that changed and the controls that must not — a brace inside inline code, and the passed-in code index), `_data/_captions` (a caption ending in `\\`, and one holding `\\{b}`), `_data/_sections` (a heading ending in `\\`), `_styles.js` (the `listsStyles` snapshot and a no-bare-`ul`/`ol` tripwire).

Two invariants are load-bearing enough to have been checked by mutation rather than trusted: neutralising the `env` rollback fails 8 tests, neutralising the transient restore fails 2.
