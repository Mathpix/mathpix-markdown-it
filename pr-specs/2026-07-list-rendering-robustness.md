# PR: List rendering robustness fixes

Status: Implemented
Owner: @OlgaRedozubova
Base: master
Version: 3.1.0

Why a decision was taken is commented at its call site; what a consumer must do is in `doc/changelog.md`; the shapes are in the fixtures. This document holds what none of them does: the rule per fix, the boundaries, the alternatives already measured and rejected, and the numbers.

---

## Context

Several unrelated inputs made LaTeX `itemize`/`enumerate` lists render incorrectly. The fixes touch the list-env, tabular and footnote block rules, the marker-width helpers (`common/display-width.ts`) and the marker-padding CSS. They ship together.

## Goal

Fix the reported list defects — clipped markers, empty `<>` item bodies, shifted `Figure N`, a swallowed list after a paragraph, content dropped from the tabular-cell export — without changing HTML for input that already rendered correctly. Marker indent must scale with the container `font-size`, and malformed input must not degrade quadratically.

## Current Behavior

Marker width is `String.length` over `text` tokens, so wide, math and wrapped markers are undercounted and clip; padding is `px` and only on the outermost list. A speculative list parse leaks `env` flags and caption counters. `\footnote` scans swallow a following list. Inline content sitting directly in a `\begin{tabular}` cell never reaches `table-markdown`/`tsv`/`csv`. `\itemsep` is mistaken for `\item`.

## Fixes

1. **Marker padding is measured on both item paths**, where it ran on the inline one only, so a list whose long-marker items all hold a block env lost its `padding-inline-start`.

2. **Marker width covers wide, math and wrapped content** — East-Asian Wide/Fullwidth, math via rendered `widthEx`, wrapped markers via their children — where it was `String.length` over `text` tokens. It stays an estimate reserving per glyph *class* against a Helvetica/Arial-like font, with four bounds: a code point a later Unicode declares Wide under-reserves by 25% until the snapshot is updated, math is measured under SVG output only, an image marker reserves by its alt text, and the em arithmetic assumes one `font-size` down the chain plus the stylesheet's `2.5em` per ancestor. Above the `20em` clamp, and for a textless item followed by a wider-marker sublist, markers can overlap — the latter reproduces LaTeX.

3. **A speculative list parse leaks no state.** Transient `env` flags go back on **every** exit, commit included, a leaked `isBlock` having produced empty `<>` items on the next block; the rest goes back only when the tokens are discarded — every `env` key the parse touched, diffed against a snapshot so a rule the list code never heard of is covered; the figure/table counters (a figure in a list is `Figure 1`, was `Figure 3`); and the level stack, snapshotted structurally so both a removed level and the `openItems` of a surviving one come back, that count deciding whether a chunk before the first `\item` gets its `<li>`. A rule that throws answers "no list" and warns once per cause per render, only a failure past the commit point propagating; the dedupe caps per cause family (40 keys) as well as overall (200), so a document minting hundreds of `list-rule-failed:` keys cannot silence another subsystem's one warning.

4. **Footnote scans stop at a list start**, so a list right after a paragraph is no longer swallowed; the `\footnote` scan takes the list rule only when an opener sits ahead of the block. An unclosed env short-circuits twice — before parsing when the source holds no closer, and during the body walk when the closers ahead are fewer than the envs open, the second able only to keep the walk going since the sweep over-counts closers. Interleaved real closers and unclosed envs are improved, not fixed: `N^1.7` with every tenth unit closed and `N^1.9` with every other, against `N^2.0` on `master`.

5. **Marker padding is in `em`**, so the indent and the `0.625em` gap scale with the container `font-size`; a custom `padding-inline-start` is emitted only when the marker overflows the default `2.5em`, attributed per nesting level, clamped at `20em`, carrying its unit (`"4.23em"`). A level reserves the shortfall its ancestors leave, so it can only fall short when the clamp caps the chain sum.

6. **`\item` detection requires a real command**, anchored on `\item` plus a command boundary, so `\itemsep`/`\itemindent` and the bare word "item" no longer split an item or break a multiline `\footnote` inside one.

7. **Markdown lists indent `2.5em`, not the UA `40px`** — core-markdown `<ul>`/`<ol>` get a scoped `#preview-content`/`#setText` rule that scales with the container, the numbered footnotes list included, in wrapped output only. `2.5em` equals the UA default at a 16px base, and `PreviewStyle` sets `#preview { font-size: 17px }`, so such a list sits at `42.5px` per level. A TOC under `#toc_container` or `.table-of-contents` is zeroed twice, by this rule at `(2,0,1)` and by `padding: 0` from `TocStyle` later in order; copied elsewhere it matches no TOC rule and shifts `2.5px` per level.

8. **Inline content in a tabular cell reaches the export**, where it was rendered to HTML only: a link swallowed the rest of its cell (`[a](http://u) tail` exported as `| [a](http://u) |`) and a one-line nested list lost its sublist bodies. A flat one-line list changes too when the cell holds content before the first `\item` — `\begin{itemize} loose \item a\end{itemize}` exports `" loose \n • a"` against `master`'s `" • a"`, that chunk now having an `<li>` of its own (fix 17) — and only a flat list with nothing before its first `\item` is untouched.

9. **A link in a tabular cell keeps its label and closes its anchor** — pre-existing and unrelated to lists, fixed here because it shares the cell-export path. The label is read whole with `]`, `[` and `\` escaped, while math and an image alt pass through verbatim as source slices carrying their own escapes, math taking the cell delimiters (`$…$` for display math too, a backslash there changing the LaTeX) and an href a bare destination cannot hold taking the `<…>` form. What the export cannot restore is an escape the parser already consumed: `[a\*b\*c]` reaches us as the text `a*b*c`, so it exports unescaped, as on `master`.

10. **Unclosed `\begin{tabular}` short-circuits**, checking for a closer before scanning to EOF instead of after; still super-linear for the reason under Boundaries. Not list-related, and included because the same probe-per-line pattern reaches it from the same input.

11. **A line can carry several env transitions**, all handled in source order — before, one per line was handled and the rest became item text, so the outer list never closed and the strict no-partial-tokens bail dropped it as literal text. A collapsed `\end{itemize}\end{itemize}` closes two levels, a mid-line closer can open a sibling, a second sublist on one line is no longer lost, a nested list carries its own line range under `lineNumbering`, and text before a transition opens its own item when it carries a marker. A sibling opens only when the closers ahead **cover** what its tail leaves open, counted — an unclosed sibling aborts the rule and would take the finished list with it. Termination is by construction, every match consuming at least `\end{itemize}`, and the only change on already-correct output is a whitespace-only text node between `<ul>` and `<li>` that no longer appears.

    - **A leftover after the outermost closer goes back to the block phase**, where `\end{itemize} tail text` used to lose `tail text` — the rule reported success having dropped input. The line's marks move on commit only, the arrays being shared with the real state by prototype; only `bMarks`/`tShift` move; the offset is anchored on the line's end, four branches handing the walk a line with a prefix already eaten; and a range check drops the leftover rather than move the marks outside the line. A leftover holding list structure stays with the walk: read as a fresh document it would open as a top-level list, skipping the closer count that keeps `\caption{ \end{itemize} }` from opening a sibling.
    - **The opaque pass may not take a prefix that holds a transition**, or `\end{itemize} \begin{center}x\end{center}` leaves the closer uncounted and the whole list comes out as literal LaTeX.
    - **A paragraph may not end inside a list env its own lines opened** — `paragraphDiv` read an opener only at a line start, so `text \begin{itemize}` broke the paragraph on the next opener, on `master` too. The gate reads the line through `maskNonStructure`, so an opener in code or in a marker does not fire it, and it is asked of every line rather than the first: a false yes costs one question, a false no costs the fix. Two guards keep the cost where it belongs — only a paragraph holding a mid-line opener asks, and the field is cleared right after the terminator loop, a stale one having made a footnote scan decline a list.
    - **A backtick run with no partner is text, so nothing after it is code**, where `skipBackticks` returned the end of the source and the inline scanner read a list's own `\end` as code. Inherited, `master` included.

12. **A block env in a list body reaches the block rules wherever it sits.** `finalizeListItems` block-parsed an item only when its content held a block env **and** an `\item`, so a chunk with one but no marker — after a closed sublist, or before the first item — fell to the inline path: `\begin{table}` leaked as text, `\captionsetup` left a stray `}`, the caption was dropped. Such a chunk is block-parsed into the open item now, gated by the same `LATEX_BLOCK_ENV_OPEN_RE` as the marker case so the two paths agree by construction; backtick and tilde fences stay on the inline path, block-parsing them having printed the backticks and lost the code.

13. **A wrapper env is opaque to the list scanner.** The body walk reads `\item` and `\end{itemize}` textually, so a list command inside a `table`/`figure`/`center`/`left`/`right` was taken as structure: `\caption{\item[a]}` gave no items at all, a stray closer in a caption closed the list after one, an `\item` inside `\begin{center}` produced three. Those five envs join `tabular` and `lstlisting` on the opaque stack, their lines collected raw until their own closer. The input is invalid LaTeX, so the aim is well-formed degradation; every decline path equals `master`, and it lives in `md-latex-lists-env/latex-list-opaque`.

    - **A wrapper turns opaque only when its `\end` is ahead and reachable**, measured from the `\begin` itself: anchored on the line, an `\end{X}` left of the opener reads as reachable and three shapes lose the whole list.
    - **Order, not a tally** — a closer standing first inside the wrapper is ours even when openers follow, answered by one merge walk over two ascending offset lists.
    - **A closer inside a *supported* command's argument is text**: `\caption{x \end{itemize} y}` does not end the list, while `{x \end{itemize} y}` and `\foo{x \end{itemize} y}` do, Markdown keeping braces in prose and a name the package does not parse being text with them. The names are one frozen list, `LATEX_BRACE_ARG_COMMANDS`, the sweep built from it so the two cannot drift, and every name is pinned by a test — a sweep for `\name` in the source misses the underline family and `\author`, which build their names by alternation. `\alph|\Alph|\arabic|\roman|\Roman` are deliberately absent, their pattern admitting only `enumi…enumiv`, so no closer can sit in an argument that is parsed at all.
    - **Argument spans are paired once per source** in `common/argument-spans.ts`, so the caption and footnote readers reuse them: `braceMatches` records where each balanced `{` closes in one stack pass, `commandArgumentSpans` reads forward from the supported names and keeps the outermost, ascending. A bare `\name` is skipped only at the command name, there being no such form between arguments — skipping one there took `\textbf{x}\unknown{q}` for two arguments of `\textbf`.
    - **An argument left open marks nothing, and a brace with no command before it blinds nothing** — `\caption{x \end{itemize} y` shields no closer, and the `{` of `$\frac{1}{2$` is not an argument, so every pair around it is still classified.
    - **Content a parser reads verbatim is text, everywhere the guard looks**: `common/verbatim-ranges.ts` locates fenced blocks, `lstlisting` bodies, inline code and math once per source, math asked for environments only so `\begin{itemize}` never reads as a formula. Math is scanned **per paragraph**, its rules pairing inside one inline token — over the raw source a `$` paired with one nine paragraphs away and marked the list between them verbatim — and a `$` whose partner lies past its paragraph is dropped, while an env keeps the clipped span, its body being allowed to span paragraphs.
    - **Text is text for every reader**, one predicate `writtenAsText` asked by four: the closer a wrapper wants to reach, whether our closer stands inside the wrapper, how many closers a tail still needs, and whether a sibling can close what it opens. Each one that asked half of it cost an item; the fifth reader, the inline scanner, is a boundary.
    - Four contexts hold braces and closers without being modelled as verbatim — `\verb`, an indented block, an html block and a `tabular` inside the wrapper — and render correctly for another reason, so a change that needs them read as verbatim must add them to the ranges.
    - **A closer of ours written inside the wrapper is content**, provided the source past the wrapper still closes the open lists: `\begin{center} text \end{itemize} here … \end{center}` between two items keeps both and renders the wrapper, what stands inside going to the wrapper's own rule, a list opened there included. How many lists are open is read at the moment of the decision through `getOpenListCount()`, levels being entered during the same walk.
    - **The one-line form is decided in one helper both openers call** — written twice, the nested-`tabular` branch had only the opening half, so `A & \begin{tabular}{l}x\end{tabular} \\` in a list body printed the whole list as literal LaTeX, on `master` too. Wrapper names, closer patterns and cache keys all derive from one list in `consts.ts`.

14. **A list inside a wrapper env keeps its nesting depth.** Wrapper content reaches the block rules from the *inline* phase on a synthetic state that cannot see the enclosing list, so a list parsed there claims top level and the renderer reset its depth: any of the five wrappers between two `itemize` levels gave `•  •  •` where an unwrapped list gives `•  –  •`, `enumerate` gave `decimal | decimal`, and the counter was left negative for the item after. Both branches reset only when no list is open, and the per-render reset lives in one place called from `reset_mmd_global_state` — load-bearing drift recovery, since gating the branches without it fails 8 tests.

15. **Three caches that were not caching**, all three costs pre-existing on `master` and asked often enough by this change to matter. Each is hosted on `env`, emptied per render and released again from a rule pushed after `inline`; a nested `md.block.parse`/`md.inline.parse` reaches neither hook, so it can neither clear an outer document's entries nor leave its own behind. **Marker macros** were re-parsed through the inline parser on every list open, 12–16 times per list block, and are parsed once per macro per render now, a mid-document `\renewcommand` still switching markers; every read is a copy with its own `attrs`, `children`, `meta` and `map`, the originals staying `Object.freeze`d so a path that ever returned one uncopied fails there instead of leaking. **Source sweeps** lived on the state object while block rules ask through a buffered probe whose own properties die with it, so a sweep reran per probe; on `env` the probe inherits it by reference, one entry per `src`, evicted by age with a hit refreshing its slot, and a hot slot in front of the map answers the current source by identity. **The terminator set** was resolved from the block ruler for every block ahead of the last footnote, and is resolved once per ruler state now, keyed by the ruler's compiled cache, which markdown-it nulls on any `enable`/`disable`, so a rule toggled at runtime is probed or dropped at once.

16. **`findEndMarker` reads an escape by parity, not by the previous character**, `\\` being a line break in LaTeX: `{a\\}` reported no match, `{a\\{b}` a match where nothing closes, `{a\\{b}}` closed on the inner brace, and end to end `\caption{first line \\}` produced no caption and `\section{title \\}` no heading. Pre-existing on `master`, fixed here because the list guard pairs arguments through the same helper. A `[...]` option also has one reader instead of three, which disagreed on four of eight forms — a `]` inside a code span, `\]`, `[[m]]`, a `]` one line down: `skipOptionalArg` takes the line rule as a parameter, span readers allowing an option onto the next line and offset readers not, and an unclosed option costs the line rather than the document.

17. **A chunk before the first `\item` gets a marker-less `<li>`**, `<ul>` admitting only `<li>` where such a chunk went in beside them. The wrapper carries what a written item carries for the same content — `li_itemize`/`li_enumerate not_number`, the `block` class for block markup, the `data-custom-marker`/`data-marker-empty` pair, line numbering spanning what it wraps — and takes the custom-marker shape inside `<ol>`, a plain `<li>` there being counted by the browser, which moved every number below it by one. It is applied **after** the chunk's tokens are emitted, so a run that emitted nothing is not wrapped: deciding in advance meant predicting emission from the text, with another predicate per shape. All three emission points are covered, the same-line one in `ListOpen` not redundant — `\begin{itemize} loose \item x \end{itemize}` emits its chunk there and nowhere else. The token is built through `state.Token`, so the inline path's synthetic state carries the constructor a real `StateBlock` has; without it the rule throws and a list inside a paragraph or a cell drops to literal LaTeX with one warning, whose absence the tests assert alongside the HTML. A sublist written in the chunk goes **inside** the wrapper, or the `<ul>` would be a direct child of a `<ul>`; a chunk *between* two lists belongs to neither and takes no `<li>`.

18. **A command written in an argument is text, for every reader**: `maskNonStructure` hides code spans and `\item[…]` markers before the walk looks, `renewCommandSpanEnd` measures a `\renewcommand` so its body is skipped whole, and both scanners plus `unclosedEnvsIn` read the same masked text. What this reached: an `\end{itemize}` beside a code span closed a second list from inside item content, leaving a stray `</ul>`; a list command in a marker cost the whole list; `\renewcommand*`, `{\x}[1][d]{…}` and a bare `\name` were unmeasured, so the closer sharing their line was swallowed. A span that cannot be measured at all goes to the walk instead, keeping its `<br>` — losing the closer is the worse trade.

    - The tail that may open a sibling is read masked too, by the same slice the walk steps on so the two cannot drift: unmasked, an opener in a code span counted as a sibling and the closer after it emitted a `</ol>` with no opener.
    - A run left at list level gets its `<li>` wherever it comes from, fix 17 having covered the block path only; `wrapListLevelRuns` reads the emitted tokens after a list open or an item close rather than hooking a rule, the item close belonging to whichever rule owns the list. What it must not wrap is a run that renders to nothing: `\setcounter` and `\renewcommand` are applied, not printed, so their `<li>` was invisible in the HTML while a consumer walking the token stream read an `\item` the source never had — asserted on the stream for that reason.
    - `ItemsAddToPrev` reads the masked line as well: it drops a chunk that is only an end-of-list command, and unmasked it dropped `keep \`\end{itemize}\` me` whole, the list rendering as `<ul></ul>`. Inherited from `master`, reachable only once the walk started reading spans as text.
    - The marker body is parsed with the block flag still set on `env`, so a list written there opened a real one inside `<span class="li_level">`; all three marker parses are guarded by a counted flag, and `\item` with no list open stays text rather than emitting an `<li>` with nothing to sit in.
    - Not covered: `writtenAsText` pairs `{}` only, so the closer sweeps still count one written in an `\item[…]` — over ten shapes built to reach it the over-count changes no rendered document, the counters being a conservative bound by design, and teaching `commandArgumentSpans` about `[]` touches the source of truth every scanner reads.

19. **The block `\renewcommand` rule claims its line only when nothing shares it**, where it consumed the whole line and renders to nothing, so text beside the command was dropped — in a list body once a chunk with a block env took the block path, and in any document before that. It applies the command and returns `false` when a tail remains, so the paragraph keeps the text and the inline rule reads the command; fixing it in the rule is what makes a guard unnecessary, no block rule running inside a fence, `lstlisting` or `tabular`. Over a 1728-shape grid 268 forms change and none loses text, 16 of them differing from `3.0.1` — each a `\renewcommand{\x}` with no body, keeping the line below that `3.0.1` swallowed. Two things follow. The token's `latex` is written per rule and the LaTeX converter reads both shapes — the block rule gives the command, the inline one everything past the name — so a tail moves the line to the inline rule and that payload changes with it. And `parseOneCommand` reports the length of what is left when the arguments do not close, so the inline rule is bounded to its own line, the same line the block reader measures, where it had set `state.pos` past `posMax` and the tokenizer dropped every line after it; that also fixes the older mid-paragraph form, broken on `master` too.

20. **Both readers of a `\diagbox` argument share one code index**, each having built the inline-code index over the whole string twice per command. It is built once per string in the block path and once per source in the inline one, the arguments read at absolute offsets in `src` — so the position the inline rule ends at is absolute too, which is what the fixtures pin. Without a backtick in the string the old code was already linear, `getInlineCodeListFromString` returning at once, which is why the axis needs a code span past the commands to show anything.

## Boundaries

- **Text between `\begin{itemize}` and the first `\item` stays inside the list**, LaTeX rejecting text there so there is no item to attach it to; it is no longer a direct child of the `<ul>` (fix 17), and a `table`/`figure` float in that position is a different case and is fixed (12).
- **A leftover after the outermost closer is kept unless it holds list structure** — fixed for text, a `}`, a code span and a fence opening (fix 11), not for a wrapper env: the list rule is asked first (position 15 against `paragraphDiv`'s 29) and declines the line, and in the paragraph a `center` has no rule to render it while `tabular` and `lstlisting` have an inline one. Eight `center`/`figure` shapes changed against `master`, which dropped the wrapper; a leftover that opens a list of its own is still dropped, byte-identical to `master`.
- **Two cell-export quirks stay**: a `|` inside math is exported as `\|` and no table parser unescapes it there, so the LaTeX changes meaning — unavoidable, an unescaped `|` splitting the cell — and a list exported from a cell ends with a `<br>`, the separator closing every item.
- **Diagnostics go to the global `console`, and a degraded render leaves no programmatic signal**, there being no channel to use: `ParseErrorList` is written by the tabular path and never read, `ParserErrors` is an enum of math display modes. The coverage side is closed by `listRuleFailureCount` and a root hook asserting zero over every test — a degraded list is valid output, so no fixture, grid or fuzz invariant reports one, and an injected `TypeError` passed the whole suite without the hook.
- **A closer written in `$…$` outside a wrapper still ends the list**, the body walk reading its line textually and never asking `writtenAsText` — byte-identical to `master`, and text inside a wrapper, which collects its interior raw. Teaching the walk the model means giving it offsets instead of line text.
- **The inline scanner still walks character by character**, though it no longer copies the source to do it; that walk is what remains super-linear in principle, and it dominates nothing measured here.
- **The five list inline rules keep their `src.slice(pos)` at entry**, `BEGIN_LIST_ENV_RE`, `END_LIST_ENV_RE` and `reSetCounter` being anchored, so the match fails at offset 0 and the tail is never read: 14 ns per call against 10 ns for a sticky exec, and flat from a 1KB tail to 1MB, which is what proves it. The slices that did cost fed an unanchored scan or an index build — fix 20 and the scanner above.
- **`absoluteOffsetOf` answers -1 without a warning**, its callers having to pass a suffix of the line and it declining when the text at the offset it computed does not confirm; that branch is never reached over the corpus and the fuzz, so a warning there would never speak, and a test on the function pins it instead.
- **The per-source caches keep eight entries per key and say nothing when they evict**, so on the inline path — where a "source" is a paragraph or a cell — a document with more than eight of them asking one key starts recomputing. No cliff is observable at document level — over documents of 4, 8, 20 and 40 such paragraphs the cost per paragraph falls, 0.88/0.41/0.20/0.15 ms — and pricing the eviction itself needs an operation counter rather than a clock. The recompute path of `srcValueCached` rewrites its slot in place and re-inserts nothing, which is sound because `recall` runs before the freshness check and has already made that source the newest entry and the hot one — pinned by a test that fails when the two are reordered.
- **With no `env` the caches fall back to the state, and such a cache is never cleared**, which every parse path avoids by having an `env` by the time a rule asks — reached 3 times in a full suite run against 35174 on `env`, all three the unit tests' hand-built states. Nothing shares through the prototype either, a buffered probe inheriting `env` by reference: 0 of 2.4M reads went through the chain. The ceiling, if a consumer does reach the fallback, is 18 keys × 8 sources.
- **`prentLevel` keeps its typo**, inherited from `3.0.1` and made useful by this branch rather than always `0`, so a consumer may read it; renaming touches 28 sites and the token a consumer sees.
- **The section and theorem counters are not rolled back with a discarded parse**, where the caption counters are (fix 3), and nothing reaches them today — a `\section` in a list body stays text, so no counter sees it. What remains is the missing guarantee for a rule that starts parsing such a body.
- **Malformed input with no blank lines is still super-linear**, whichever env is unclosed: the terminator probes are cheap now, but `newTheoremBlock` and markdown-it's `lheading` still scan forward from every block start without terminating — 9.2M block-rule calls at 400 units, against 23k with those two disabled. A blank line between blocks avoids it.
- **Five wrapper shapes stay as they are**, each measured identical to `master` unless noted: a spaced `\begin {center}` builds no wrapper, the shared open regex admitting no space; a wrapper inside a `tabular` cell loses the table and renders a bare `center` div, where `master` prints the whole list as LaTeX for the one-line form; a closer in a code span inside a wrapper costs the code span and, on the multi-line form, the text after it, the wrapper's own block rule truncating its content there and that rule serving every document; a wrapper closer inside a command argument on the wrapper's own line is taken as the wrapper's own; and a wrapper whose closer sits in a fence or `lstlisting` finds no closer it can use and stays transparent.
- **A list opened mid-paragraph still loses its outer level when another block rule owns the line after its closer** — one shape in two dresses, a wrapper on its own line and a fence after the closer, neither line the list rule's to take: they go to the align/float and fence rules first. A list in a `tabular` cell is the same story with the cell as owner.
- **A line still has two readers, in sequence**: the opaque pass reads it whole, then the walk reads its transitions in source order, so ownership of a stretch of line is answered by call order with a guard on top, and a third reader or a change of order brings the class back in a new shape. The structural answer — one walk asking for the next event by offset — also retires `absoluteOffsetOf`, the trim/offset coupling around the tail and the duplicated one-line wrapper helper, so it is a task of its own; the grid of 156 shapes is here to fail if the invariant slips.
- **A list left unclosed is not closed for it, so a wrapper holding its only closer prints as text.** Rendering it anyway means closing an unclosed `\begin{itemize}` implicitly, which decides the fate of every unclosed list in every document, not just this crossed shape.
- **A wrapper nested inside another of the same name loses both frames**, the opaque stack popping on the first `\end{X}` with no per-name depth; valid LaTeX, the multi-line form byte-identical to `master` and the one-line form keeping a `<div>` that `master` drops.
- **A leaf render rule runs twice in a table cell when an export is requested**, so a rule with a side effect fires twice, while renders per token stay constant as the run grows. Reading the HTML pass instead means threading it through the cell accumulators.
- **The marker registries stay outside the speculative rollback**, the line being document content whichever way the list around it parses.
- **The speculative-parse isolation has boundaries**, two of them visible to a consumer: the `env` rollback compares values by identity, so a key whose object a rule mutated in place is left as the parse left it, and it diffs the whole `env`, so its cost follows the size of the object passed — 62 ms on 200 list units, 164 with a thousand extra keys on it. Both restores first ask whether the snapshot is the innermost one, restoring from an emptied slot having blanked every key the consumer owned.

## Alternatives measured and rejected

| Instead of | It cost |
|---|---|
| Memoizing the footnote probe answers (4) | slower on every shape, with the two short-circuits in place |
| Taking the list rule into the footnote probe set unconditionally (4) | +12% over `3.0.1` on 400 paragraphs with a trailing footnote |
| Asking the paragraph gate on every line, not only in a paragraph with a mid-line opener (11) | 1000 unclosed units: 2761 ms against 61 ms |
| Rebuilding the option's code-span index per `[` (13) | 381 ms at 1000 options against 0.8 ms |
| Scanning math to EOF per paragraph (13) | 126 ms on 113 KB of prose against 1.2 ms |
| Keeping the source sweeps on the state instead of `env` (15) | 1001 sweeps where 6 suffice, on 200 units with a wrapper per list |

## Breaking change / migration

The canonical list is `doc/changelog.md` under **Breaking changes**, each entry with what a consumer must do; the entries under **Fixes that change existing output** replace output that was broken or invalid, so a consumer diffing HTML sees them but has nothing to change. Migration, in the order it bites: readers of `data-padding-inline-start` must parse an em value with its unit; anyone reading a `tsv`/`csv` cell as an address must stop, a link contributing its href with the rest of the cell after it; anyone importing `lib/styles/styles-code` alone must also emit `MathpixStyle` for code text to keep its size; a TOC copied into a container other than `#toc_container` needs its own `padding: 0`.

## Testing

Rendered output is locked by full-HTML fixtures — `_data/_lists`, the pinned quirks in `_data/_lists/_data_known_quirks.js`, plus the caption, section and footnote sets. Every shape named in this document is among them, including the ones that stay broken and the controls that must not break with them. Counts live in the files, not here. "The corpus", where a measurement names it, is every source in `tests/_data` — about 1400 of them — rendered in three output modes.

Checked as invariants, because an example would pass while the rule was broken:

- **Every direct child of every list element is an `<li>`**, swept over all list fixtures; reading only the first child passed while an invalid `<ul>` sat second.
- **No random combination of list fragments produces a tag without its partner**, crossed tags, a non-`<li>` child of a list, or list markup inside a marker — `tests/_lists-fuzz.js`, seeded. Copied into a `master` checkout the default corpus fails on 6 documents, so the assertions bite; over the same 6000 documents `master` violates them 567 times and the branch point 5. Two classes are excluded by name: a list with no item, and one `KNOWN` shape pinned in the quirks file.
- **Argument spans come back ascending, disjoint and on real braces**, over twenty thousand random brace strings, half with a verbatim range — the search over them is binary, so a nested pair leaking in makes a brace inside an argument open a new one, and the alphabet carries supported and unsupported command names or the invariants would hold over nothing.
- **As many lists out as openers in, and the follower reaches the output**, over two list kinds × three depths × seven followers × three separators × with and without an item before the closer, and the same grid with the opener mid-line. The follower assertion is what the other two cannot see — it can vanish while the level count and the no-literal check hold, which is how a regression dropping a `tabular` at depth 1 passed this grid — and shapes where a follower is still lost are listed by name with their owners.
- **Every command on the brace-argument list shields a closer written in its argument**, asked of each name with an unsupported one as control, nine having been invisible to a sweep for `\name`; and **glued and spaced read alike** over 180 forms, `\textbf{x}\unknown{q}` having been read as two arguments of `\textbf`.
- **`isInsideRanges` agrees with a linear scan at every offset** of twelve verbatim shapes, and **no shared `g`/`y` regex is left hot by a render**, asserted over every such constant of `common/consts.ts` — which found `RENEWCOMMAND_STICKY_RE`.
- **Repeated units parse linearly**, each axis of the Measurements table bounded by growth against a linear control in the same process rather than by wall clock, the ratio taken as the median of three since the lowest of three biases down — the direction that hides a regression.
- **A leaf run in a table cell costs a constant number of renders per token**, and **the guard table pins the exact item count `master` renders per shape**, a `> 0` assertion having passed while an item was lost.
- **A closer whose line lost a prefix keeps its levels, leaks no LaTeX and keeps the leftover**, over 13 prefix kinds × two list kinds × two depths × with and without a leftover; 52 of the 104 cells broke before the anchor moved to the line's end, and no fixture reached them.
- **No offset fails its anchor**: `absoluteOffsetOf` counts what it could not confirm and a root hook asserts zero — never taken over 45000 renders in three modes.
- **No test leaves the list rule degraded**, the catch that keeps a failing rule from failing the document also hiding a fault of ours, so a root hook fails the run on any test whose render went through it, verified by injecting a `TypeError`; and **no test leaves a snapshot un-released**, the depth being module state — a test that died before its release left it raised, and from then on both restores declined, so one failure read as four. Both hooks live in `tests/hooks/root-hooks.js`, required through the `mocha` key in `package.json` so they cover a run of one file too.
- **Every `KNOWN` entry of the fuzz corpus matches a document**, asked at the default size or above, or the exclusion would go quiet rather than go away.
- **The deep sweep runs before a merge or a release**, 25000 documents against the default 2000; seeded, so repetition buys nothing and only a code change makes it mean something again, and since a default run cannot reach the zone the last defect came from it reports the omission as a pending test rather than passing in silence.

Two invariants were checked by mutation rather than trusted, each by an early `return` at the function's entry: neutralising `restoreEnvAll` fails 11 tests, `restoreEnvKeysFromAll` 8.
