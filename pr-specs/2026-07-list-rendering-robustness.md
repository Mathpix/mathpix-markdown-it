# PR: List rendering robustness fixes

Status: Implemented
Owner: @OlgaRedozubova
Base: master
Version: 3.1.0

---

## Context

Several unrelated inputs made LaTeX `itemize`/`enumerate` lists render incorrectly. The fixes touch the list-env, tabular and footnote block rules, the marker-width helpers (`common/display-width.ts`), and the marker-padding CSS. They ship together.

## Goal

Fix the reported list defects — clipped markers, empty `<>` item bodies, shifted `Figure N`, a swallowed list after a paragraph, content dropped from the tabular-cell export — without changing HTML for input that already rendered correctly. Marker indent must scale with the container `font-size`, and malformed input must not degrade quadratically.

## Non-Goals

- **Text between `\begin{itemize}` and the first `\item` stays inside the list, not before it.**
  - LaTeX rejects text there (`Something's wrong--perhaps a missing \item`), so there is no item to attach it to. Keeping it visible is deliberate; moving it out to a sibling before the list is not attempted.
  - It is no longer a direct child of the `<ul>` — fix 17 gives it a marker-less `<li>`. `\itemsep`/`\itemindent` arrive whole there rather than split into an item (fix 6), and stay visible: unsupported commands are shown, not swallowed.
  - A `table`/`figure` float in that position is a different case and is fixed (12): LaTeX accepts a float before the first item, it contributing no horizontal material.
- **Text after the outermost closer on the same line is dropped**, as on `master`: `\end{itemize}\end{itemize} trailing` loses `trailing`, because the walk has already flushed its items when that tail arrives and a block rule cannot hand a line's remainder to the next rule.
- **Two cell-export quirks stay as they are.** A `|` inside math is exported as `\|`, and a table parser does not unescape it inside the math (measured: the content reads back as `a\|b`), so the LaTeX changes meaning — unavoidable in this format, since an unescaped `|` would split the cell. A list exported from a cell ends with a `<br>`, because the separator closes every item: `| 1. a<br>2. b<br> |`. Both are pinned by fixtures.
- **Diagnostics go to the global `console`, and a degraded render leaves no programmatic signal.** A failing list rule warns once per cause and does not apply, so the caller gets degraded HTML rather than an exception and cannot tell from the return value. There is no channel to use: `ParseErrorList` is written by the tabular path and never read, `ParserErrors` is an enum of math display modes. A diagnostics surface or an injectable logger is a library-wide change of its own.
- **A closer written in `$…$` outside a wrapper still ends the list.** The body walk reads its line textually — `nextListEnvMatch` over `maskNonStructure`, which hides code spans and `\item[…]` markers — and never asks `writtenAsText`, which the four readers of the source model do, so math is not among what it hides. So `\item a $x \end{itemize} y$` closes the list at that closer and prints the rest as literal LaTeX, byte-identical to `master`; inside a wrapper env the same closer is text, because the wrapper collects its interior raw. Pinned as a quirk. Teaching the body walk the model means giving it offsets instead of line text, which is the change the inline scanner needs too.
- **The inline scanner is still super-linear in the items of one list.** `findFirstCompleteListEnv` walks character by character and slices the rest of the source at each step, so a list written inside a paragraph or a cell costs more than linear: 3.0 / 4.1 / 8.4 / 26.8 ms at 100 / 200 / 400 / 800 items, i.e. ×3.2 on the last doubling. Measured identical to `master` (2.8 / 4.5 / 9.0 / 27.8), so it is not a regression — but the linearity this document claims is about the block guard's sweeps, not this path. Rewriting it needs sticky regexes and an index-based scan, as the item scanner beside it already has.
- **Malformed input with no blank lines is still super-linear**, whichever env is unclosed: the terminator probes are cheap now, but `newTheoremBlock` and markdown-it's `lheading` still scan forward from every block start without terminating. Measured at 400 units: 9.2M block-rule calls, against 23k with those two disabled. Each is quadratic on its own, neither is touched here, and a blank line between blocks avoids it.
- **Five wrapper shapes stay as they are.** Each is measured identical to `master` unless noted, so none is a regression.
  - *A spaced `\begin {center}`* builds no wrapper, the shared open regex admitting no space there. The list itself renders whole — two items, nothing leaked. Widening a constant shared with other rules is a change of its own.
  - *A wrapper inside a `tabular` cell* loses the table: `\begin{tabular}{l}\begin{center} x \end{center} \\\end{tabular}` between two items renders the cell content as a bare `center` div, on one line or three. Both items survive, where `master` prints the whole list as literal LaTeX for the one-line form. The input is invalid LaTeX, and restoring the frame belongs to how cells are parsed.
  - *A closer written in a code span inside a wrapper* costs the code span, and on the multi-line form the text after it: `x` + a code span holding `\end{center}` + `y` renders `x \`` inside the block and `x \`\end{center}` after it, the ` y` gone. The body walk skips such a closer, but the wrapper's own block rule truncates its content at it — and that rule serves every `center`/`table`/`figure` in every document, so it is out of scope here. Identical to `master`, pinned with a control shape.
  - *A wrapper closer written inside a command argument on the wrapper's own line* is taken as the wrapper's own: `\begin{center}\caption{x \end{center} y}\end{center}` closes at the inner one, leaving `y}\end{center}` as a paragraph below the div. The closer sweep is argument-aware for later lines, but the same-line check stays off — turning it on was measured to drop the tail of the line instead. Both items survive; `master` builds no wrapper here and leaks the whole line.
  - *A wrapper whose closer is written inside a fenced block or an `lstlisting`* finds no closer it can use — that text is code — so it stays transparent and the list renders one item, as on `master`. A fenced block elsewhere between the `\begin` and the closer decides nothing: the guard asks whether the closer *sits inside* verbatim content, not whether a fence opened before it.
- **A wrapper nested inside another of the same name loses both frames.** The opaque stack pops on the first `\end{X}` with no depth count per name, so the list and one centred block survive while the inner opener and the outer closer come out as text. Valid LaTeX. The multi-line form is byte-identical to `master`; the one-line form differs by keeping `<div>tail \end{center}</div>`, which `master` drops. Both pinned, so a per-name depth counter added later reads as deliberate; `tabular` already has one in its own branch.
- **A leaf render rule runs twice in a table cell when an export is requested**, once for HTML and once for the run as a whole, so a rule with a side effect fires twice. Renders per token stay constant as the run grows (pinned). Measured on 50 math cells: `include_table_markdown` and `forPptx` add nothing over plain HTML; `tsv`+`csv` cost ×9 here and ×8.5 on `master`, so that belongs to those formats. Reading the HTML pass instead means threading it through the cell accumulators — a change of its own.
- **The marker registries stay outside the speculative rollback.** `\renewcommand{\labelitemi}{…}` writes module-level state, and a probe that ran it leaves the definition behind. Rolling it back was tried and reverted: the line is document content whichever way the list around it parses and its own block rule applies it, so with the rollback the same source answered `•` on an instance's first render and `ZZZ` on the next. Measured on three shapes: the definition applies to the list below, alike on a fresh instance and a reused one, and identically to `master`. Pinned by a test and two fixtures.
- **The speculative-parse isolation has boundaries, documented where they live in the code.** Two are visible to a consumer: the `env` rollback compares values by identity, so a key whose object a rule mutated in place is left as the parse left it (`common/env-transient.ts`); and it diffs the whole `env`, so its cost follows the size of the object the consumer passes — 62 ms against 164 ms with 1000 extra keys on the same 200 units. Both restores first ask whether the snapshot is still the innermost one and leave `env` alone when it is not: a pool reset empties the slot, and restoring from an emptied one blanked every key the consumer owned. The rest are internal: which module-global registries are restored and why the others are not, and why the inline registry pops by token kind while the block path pops by identity.

## Current Behavior

Marker width is `String.length` over `text` tokens, so wide, math and wrapped markers are undercounted and clip; padding is `px` and only on the outermost list. A speculative list parse leaks `env` flags and caption counters. `\footnote` scans swallow a following list. Inline content sitting directly in a `\begin{tabular}` cell never reaches `table-markdown`/`tsv`/`csv`. `\itemsep` is mistaken for `\item`.

## Desired Behavior

1. **Block-content items get marker padding.** Marker width was measured on the inline item path only, so a list whose long-marker items all hold a block env (`\begin{figure}`, `\begin{tabular}`, a code fence) lost its `padding-inline-start`. The width calc is now shared and applied on the block path too.
2. **Marker width accounts for wide/math/wrapped content.** Was `String.length` over `text` tokens only: East-Asian Wide/Fullwidth (`\item[11．]`), math (`\item[$x^4+x^4$]`, via rendered `widthEx`) and wrapped markers (`\item[\textbf{…}]`, via their children) are now measured instead of undercounted.

   It stays an estimate by design, and reserves per glyph *class* against a Helvetica/Arial-like font. Its bounds: a code point a later Unicode declares Wide under-reserves by 25% until the snapshot is updated; math is measured only under SVG output, `widthEx` being filled there alone; an image marker reserves by its alt text; the em arithmetic assumes one `font-size` down the chain plus the stylesheet's `2.5em` per ancestor, so a per-level size or a consumer without that stylesheet shifts the reserve by the ratio. Above the `20em` clamp, and for a textless item followed by a wider-marker sublist, markers can overlap — the latter reproduces LaTeX.
3. **No state leak from a speculative list parse.** The rule parses into a buffered state before committing; a silent probe or abort discards the tokens.

   Transient `env` flags are restored on **every** exit, commit included — a leaked `isBlock` produced empty `<>` items on the next block. Everything else goes back only when the tokens are discarded: every `env` key the parse changed or added, diffed against a snapshot so a rule the list code never heard of is covered too; the module-global figure/table counters (a figure in a list is `Figure 1`, was `Figure 3`); and the list-level stack, pushed and popped so no half-open level closes an extra `<li>` later.

   A rule that throws does not apply — it answers "no list" and warns once per cause per render. Both paths guard themselves: the block rule for markdown-it's paragraph chain and `lheading`, the inline rule for its own call into the same engine, so whether the environment sits on its own line no longer decides between a rendered document and a failed one. Only a failure past the commit point propagates, its tokens being already in the stream; the levels and counters unwind either way.

   The opaque-env loop needs no limit on how many `\begin`/`\end` pairs one line may carry: every branch either returns or hands back a strictly shorter tail, so it ends by construction — a step count of 50 took the tail as text from the 50th pair on, and 60 nested `tabular` closed on one line reached it. The warning past that loop asserts the invariant rather than guarding it; the one guard that does report itself is the cap on the distinct-cause dedupe, past which a reader is told the log is truncated instead of complete. That cap is per cause family (40 keys, the key up to its first colon) as well as overall (200), so a document minting hundreds of `list-rule-failed:` keys cannot silence the single warning another subsystem owes.
4. **Footnote scans stop at a list start.** `\footnote`/`\footnotetext` now terminate their forward scan at `\begin{itemize|enumerate}`, so a list right after a paragraph (no blank line) is no longer swallowed as literal text.

   In the `\footnote` scan the list rule joins the probe set only when a list opener sits ahead of the block: without that gate and the resolved-set cache, 400 paragraphs with a footnote at the end cost 12% over `master`; with both they match it. The `\footnotetext` scan takes the list rule unconditionally — it already resolves a full terminator set, and gating that one measured under 1%.

   An unclosed env short-circuits twice: before parsing when the source holds no closer at all, and during the body walk when the closers left ahead are fewer than the envs already open. The second check can only keep the walk going, never cut a list that would have closed, the sweep over-counting closers (one inside a fence is not real). Probe answers are deliberately **not** memoized: with those checks in place a memo measured slower on every shape, and its key would have to enumerate every input the answer depends on. Interleaved real closers and unclosed envs are improved, not fixed — `N^1.7` with every tenth unit closed, `N^1.9` with every other, against `N^2.0` on `master`.
5. **Marker padding in `em`, not `px`.** The indent and the `0.625em` marker gap now scale with the container `font-size`. A custom `padding-inline-start` is emitted only when the marker overflows the default (`2.5em`), attributed per nesting level and clamped at `20em`; the attribute carries its unit (`"4.23em"`).

   A level reserves the shortfall its ancestors leave, so its room is the chain sum and it can only fall short when the clamp caps that sum. That is not reported: measured, a level whose own `em` goes negative because the ancestors already reserve more than it needs does **not** overlap (22.5em of chain room against a 5.34em marker), so a line keyed on the clamp fires where nothing overlaps — it told a consumer nothing to act on and could not be silenced.
6. **`\item` detection requires a real command.** `\itemsep`/`\itemindent` and the bare word "item" no longer split an item or break a multiline `\footnote` inside one; item detection anchors on `\item` + a command boundary.
7. **Markdown lists indent `2.5em`, not the UA `40px`.** Core-markdown `<ul>`/`<ol>` (no `.itemize`/`.enumerate`) get a scoped `#preview-content`/`#setText` rule that scales with the container; the numbered footnotes list is covered. Wrapped output only. `2.5em` equals the UA default only at a 16px base, and `PreviewStyle` sets `#preview { font-size: 17px }`, so in the shipped wrapper such a list sits at `42.5px` per level.

   A TOC under `#toc_container` or `.table-of-contents` is zeroed twice — this rule set at specificity `(2,0,1)`, and `padding: 0` from `TocStyle` later in order. A TOC copied into any other container matches no TOC rule at all, because `TocStyle` applies its parameter to the outer selectors only and hardcodes the inner ones; that shifts such a list by `2.5px` per level. Left alone deliberately: pairing every inner selector with the caller's name would also drop `list-style`, item padding, title sizes and link colours onto containers that never had them. The workaround is in the changelog.
8. **Inline content in a tabular cell reaches the export.** Content sitting directly in a `\begin{tabular}` cell was rendered to HTML only, its `table-markdown`/`tsv`/`csv` text dropped: measured, a link swallowed the rest of its cell (`[a](http://u) tail` exported as `| [a](http://u) |`) and a single-line nested list lost its sublist bodies (`| • a&#160;&#160;– <br> |`, the `b` gone). Both reach those exports now; HTML is unchanged. A flat one-line list was never affected — that shape exports the same on `master`. The run is handed over as a token literal with no `type`, so the `subTabular` quoting branch never sees it; passing the type through is measured identical on every shape tried, and since `tsv`/`csv` are a contract with other apps the export stays as it is, pinned by a fixture.
9. **A link in a tabular cell keeps its label and closes its anchor.** Pre-existing and unrelated to lists, fixed here because it shares the cell-export path: the link consumed two tokens too many (open `<a>`, following content absorbed), and read its label from one token, so a formatted label came out empty.

    - The label is read whole, with every character that could end or re-cut it escaped in text and raw markup: `]` closes it, `[` re-pairs with that bracket, `\` escapes what follows.
    - Math and an image alt pass through verbatim, both being source slices that carry their own escapes (`image.ts` never parses the alt). Math takes the cell delimiters, `$…$` by default for display math too, since a backslash added there would change the LaTeX — `\\` is a line break. Those delimiters are also what shields an unbalanced `]` inside math for a reader that has a math rule.
    - An href a bare destination cannot hold takes the `<…>` form, and the pptx-smoothed output no longer carries a bare `<a>` or the raw HTML of a table written inside a label.
    - What the export cannot restore is an escape the parser already consumed: `[a\*b\*c]` reaches us as the text `a*b*c` (markdown-it's `escape` rule appends to the pending buffer, leaving no token to read), so it exports unescaped, as on `master`.
10. **Unclosed `\begin{tabular}` short-circuits.** Like fix 4, `BeginTabular` checks for a closing `\end{tabular}` before scanning to EOF instead of rejecting only afterwards. Measured over 100 / 200 / 400 unclosed units: 49.8 / 181.3 / 677.9 ms against 185.7 / 1392.8 / 9697.1 on `master` — 14× at 400 units, and the growth per doubling drops from ×7.0 to ×3.7. It stays super-linear: the probes are cheap now, but `newTheoremBlock` and `lheading` still scan forward from every block start (Non-Goals), so 400 units still cost most of a second. Not list-related; included because the same probe-per-line pattern reaches it from the same malformed input, and pinned by a growth test.
11. **A line can carry several env transitions**, and all of them are handled, in source order. Before, one transition per line was handled and the rest became item text — where `ItemsAddToPrev` drops a pure closer — so the outer list never closed and the strict no-partial-tokens bail dropped it as literal text.

    - A collapsed `\end{itemize}\end{itemize}` closes two levels; a closer mid-line can open a sibling list rather than only a nested one; a second sublist on one line is no longer lost. The only change on already-correct output is a whitespace-only text node between `<ul>` and `<li>` that no longer appears.
    - A sibling opens only when the closers ahead cover what its tail leaves open — counted, not merely looked for, so a tail opening two levels needs two: an unclosed sibling aborts the rule and would take the finished list with it. Those closers are counted by the same structural rule as everywhere else, so one written in code or inside a command argument does not qualify. The sibling reports its own depth: `parentType` is put back once the outermost list closes, or it would read as nested and lose one default indent.
    - The inline path has a scanner of its own (`findFirstCompleteListEnv`), and it is the reader that decides a list written mid-paragraph or in a cell. It skips code spans, a `\renewcommand` span and an `\item[…]` marker, but not other command arguments, so `\caption{x \end{itemize} y}` below an unclosed sibling still closes it there — measured, identical to `master`, and pinned. Making it argument-aware means threading the source model into a function that today takes only a string, so it stays a boundary rather than a fix here.
    - The level stack is snapshotted structurally, not by its length, which puts back neither a level a discarded parse removed nor the `openItems` it counted on a surviving one — and that count decides whether a chunk before the first `\item` gets a marker-less `<li>`. The empty case shares one frozen array, so a snapshot taken outside any list allocates nothing.
    - A nested list opens with its own line range and gets its end when it closes, as the outer list does, so under `lineNumbering` it carries `data_line_start`/`data_line_end`/`count_line` where it used to carry none. Its opening leaves `state.startLine` alone — items read that for `data_parent_line_start`, which names the list they sit in.
    - Text before a transition opens its own item when it carries a marker, as it already did before a wrapper `\begin`. Appended to the item above instead, `\item b \end{itemize}` landed in a chunk that also held a block env, where only the first marker is read and this one printed as literal text; the input is valid LaTeX, so the second item is owed.
    - Termination is by construction: every match consumes at least `\end{itemize}`, so the tail strictly shrinks.

12. **A block env in a list body reaches the block rules wherever it sits.** `finalizeListItems` block-parses an item only when its content holds a block env **and** an `\item`, so a chunk carrying one but no marker — the env following a closed nested list, or preceding the first item — fell to the inline path: `\begin{table}` leaked as text, `\captionsetup` left a stray `}`, and the caption was dropped. Such a chunk is now block-parsed into the already-open item, no new item token, gated by the same `LATEX_BLOCK_ENV_OPEN_RE` as the marker case — the two paths agree by construction. Backtick and tilde fences stay on the inline path: they are matched by the neighbouring conditions, not by this regex, and block-parsing them printed the backticks and lost the code. Both shapes are valid LaTeX, so this is a correctness fix, not tolerance for malformed input.
13. **A wrapper env is opaque to the list scanner.** The body walk reads `\item` and `\end{itemize}` textually, so a list command written inside a `table`/`figure`/`center`/`left`/`right` was taken as structure. Measured, two items expected: `\caption{\item[a]}` gave **no items at all**, a stray `\end{itemize}` in a caption closed the list after one, and an `\item` inside `\begin{center}` produced three. Those five envs now join `tabular` and `lstlisting` on the opaque stack: their lines are collected raw until their own closer, so the interior is text and the block parse builds the wrapper from it. The input is invalid LaTeX, so the aim is well-formed degradation — the command stays visible as caption text.

    A wrapper turns opaque only when its `\end` is ahead and reachable; otherwise the stack never pops and the rest of the list is collected as raw text. Each condition answers a measured shape, and every decline path equals `master`. All of it lives in `md-latex-lists-env/latex-list-opaque` — the stack, the items and the rest of the line go in and come back out, so the parse loop keeps them and this module answers only where such a region begins and ends. Splitting it off took the parse loop's own file from 694 lines to 420, with `processOpaqueLine` and its result type as the only names crossing between them.

    - **Ahead of the `\begin` itself, not of its line.** Anchored on the line, an `\end{X}` written left of the opener reads as reachable, and three shapes lose the whole list where `master` renders two items.
    - **Order, not a tally.** One closer and one opener balance as counts, yet a closer standing first is still ours: tallying cost item `b` of `\begin{itemize}\item a \begin{center} \end{itemize} \begin{itemize}\item b \end{center}\end{itemize}`. One merge walk over the two ascending offset lists answers it.
    - **A closer inside a command argument is text.** `\item b \end{itemize}` ends the list; `\caption{x \end{itemize} y}` does not. Counting line-initial commands instead printed three other shapes as literal LaTeX.
    - **Argument spans are paired once per source**, with a stack of open positions, and cached like the sweeps. Per wrapper it was quadratic; bounding it to a window made the answer depend on argument length, so one shape rendered both items at 4000 characters and one item plus literal LaTeX at 4200. A `findEndMarker` call per brace made a run of unmatched `{` rescan the tail — `n^1.9`, 12× `master` at 8000 braces; the stack is flat (5.3 / 3.7 / 4.1 ms at 2000 / 4000 / 8000) and a scaling test pins it. One pass costs 0.03–0.73 ms over 8–155 KB.
    - **An unmatched `{` makes the spans unknowable from where it sits on**, and every closer after it in that stretch counts; a closer before it is still classified, and a `{` outside the stretch does not enter the question. Read as the end of all knowledge instead, one stray `{` blinded every list below it and each lost half its items. Trusting brace depth instead printed the whole list as LaTeX for `\caption{x`, a bare `{` and `$\frac{1}{2$` — the last ordinary in OCR output.
    - **Content a parser reads verbatim is text, everywhere the guard looks.** `common/verbatim-ranges.ts` locates four kinds once per source — fenced blocks, `lstlisting` bodies (whose closer may sit on the opening line), inline code, and math through `common/math-spans.ts`, asked for math environments only so `\begin{itemize}` never reads as a formula. Math is scanned **per paragraph**, its rules pairing inside one inline token: over the raw source a `$` paired with one nine paragraphs away and marked the list between them verbatim. A `$` whose partner lies past its own paragraph is dropped rather than clipped to the paragraph — clipping left the tail after the opener reading as math, so an unpaired `$` anywhere ahead disabled the wrapper guard for the text between them. An env keeps the clipped span, its body being allowed to span paragraphs. Opener offsets are swept once and both cursors only advance, so a paragraph holding none is skipped — 1.2 ms on 113 KB of prose against 126 ms when the scanner ran to EOF per paragraph.
    - **Text is text for every reader.** Whether an offset is written as text — in code, in math, or inside a command argument — is one predicate, `writtenAsText`. Four readers ask it: brace pairing, the closer a wrapper wants to reach, the closers a sibling list needs, and how many closers a tail still needs. Each one that asked only half of it cost an item; the fifth reader, the inline scanner, is a boundary (see above) and asks its own way.
    - Four contexts hold braces and closers without being modelled as verbatim — `\verb`, an indented block, an html block and a `tabular` inside the wrapper. They render correctly for another reason: a brace they hold pairs with nothing, and a closer written there survives by the content rule below. A change that needs them read as verbatim has to add them to the ranges rather than assume they are there.
    - Knowledge beats conservatism where it exists: a transition inside a balanced `{}` pair is text even when a `{` earlier in the document never closed. Where neither a span nor a verbatim range covers it, the transition counts as structure — the safe side.
    - **A closer of ours written inside the wrapper is content**, provided the source past the wrapper still closes the open lists and no list *starts* inside it. `tabular` always read such input that way and the five envs now match: `\begin{center} text \end{itemize} here … \end{center}` between two items keeps both items and renders the wrapper, where it used to end the list there and print the rest as literal LaTeX. The opener condition keeps the crossed-boundary shape whole — swallowing a `\begin{itemize}` written inside would lose that list.
    - **One source of truth for the names.** Wrapper names, closer patterns and cache keys derive from one list in `consts.ts`, and the guard looks for the first *wrapper* on a line rather than the first block env.
    - **How many lists are open is read at the moment of the decision**, through `getOpenListCount()`, not passed in: levels are entered *during* the same body walk, and a list opened by an outer parse still needs closing. A test pins that one wrapper body decides alike at three nesting depths.
    - **The one-line form is decided in one helper both openers call.** A wrapper that opens and closes on one line is read there, closer included: pushing the stack and handing the remainder to the item would leave it open for good. Written twice, the nested-`tabular` branch had only the opening half, so `A & \begin{tabular}{l}x\end{tabular} \\` in a list body printed the whole list as literal LaTeX, on `master` too. The tail after the closer goes back to the line walk.

    Rendering the wrapper allocates less than `master` spends on the same output: per render over 200 lists each holding one, 9.4 MB against 16.3 (`figure` 11.7 against 18.1, `table` 16.6 against 22.6, plain lists 6.8 against 14.2), same HTML and peak RSS, at 41% less wall time. Allocation must be measured with the young generation enlarged (`--max-semi-space-size`), or the number says the opposite: `heapUsed` right after a render counts young garbage, and a faster render leaves more of it — that reading was 9.4 against 2.7.

14. **A list inside a wrapper env keeps its nesting depth.** Wrapper content is collected raw and reaches the block rules from the *inline* phase, on a synthetic state that cannot see the enclosing list — so a list parsed there claims top level. The renderer reset its depth on that claim, so any of the five wrappers between two `itemize` levels gave `•  •  •` where an unwrapped list gives `•  –  •`, `enumerate` gave `decimal | decimal` for `decimal | lower-alpha`, and the counter was left negative for the item after. Both branches now reset only when no list is open, and the per-render reset — depths and enumerate counters together — lives in one place, called from `reset_mmd_global_state`. That per-render call is load-bearing drift recovery: gating the branches without it fails 8 tests.

15. **Three caches that were not caching.** All three costs are pre-existing on `master`; this change asks often enough for them to matter. Each is hosted on `env` and emptied per render, from the same hook that resets the diagnostics — before its partial-render bail, those being per-render quantities.

    - **Marker macros** were re-parsed through the inline parser on every list open, 12 to 16 times per list block. Parsed once per macro per render now, so a `\renewcommand` mid-document still switches markers. Only the array is copied on read: a render rule that writes to a marker token restamps every list of that render, and it stays that way because cloning per read measured 12–29% slower on list-heavy input — pinned by a test.
    - **Source sweeps** lived on the state object, while block rules ask through a buffered probe whose own properties die with it — so a sweep reran per probe: 200 units with a wrapper in every list ran 1001 sweeps over the full source where 6 suffice. On `env` the probe inherits it by reference, one entry per `src`, evicted by age with a hit refreshing its slot (dropping the oldest alone threw out the outer document's entry, the one asked over and over). A hot slot in front of the map answers the current source by identity, a `Map` keyed by the source hashing several KB per block-rule call. Measured: list documents 17% to 32% faster, documents without lists at parity.
    - **The terminator set** was resolved from the block ruler on every block ahead of the last footnote: 200 such paragraphs cost 200 walks over 6400 rule entries. Resolved once per ruler state now, keyed by the ruler's compiled cache, which markdown-it nulls on any `enable`/`disable` — so a rule toggled at runtime is probed or dropped at once, pinned by a test that counts a terminator rule's calls across a toggle.

    Both are also released when the chain ends, from a rule pushed after `inline` — the pattern `cleanup_math_cache` and `cleanup_tabular_state` already use. Cleared only on entry, a document's offset arrays stayed reachable on the consumer's `env` until the next render: 260 KB on a 29 KB document, most of it the argument spans. Every reader is a block or inline rule, so nothing downstream asks for them; nested `md.block.parse`/`md.inline.parse` calls reach neither hook, so a nested parse can neither clear an outer document's entries nor leave its own behind.

16. **`findEndMarker` reads an escape by parity, not by the previous character.** The helper that pairs `{`/`}` for the caption and text rules treated any preceding `\` as a shield without asking whether that `\` was itself escaped, and `\\` is a line break in LaTeX. Measured: `{a\\}` reported no match where the `}` closes, `{a\\{b}` reported a match where nothing closes, and `{a\\{b}}` closed on the inner brace. End to end, all three are valid LaTeX and this library dropped them: `\caption{first line \\}` produced no caption at all, `\section{title \\}` no heading, and `\caption{a \\{b} c}` lost everything after the inner brace. Pre-existing on `master`, fixed here because the list guard pairs arguments through the same helper. Its optional `inlineCodePositions` parameter is new for that caller: the code-span index is rebuilt per call otherwise.

17. **A chunk before the first `\item` gets a marker-less `<li>`.** `<ul>` admits only `<li>`, and such a chunk went in beside them: text and an unsupported command as a text node, a fence or a block env as an element — `master` does the same with its own shapes.

    - The wrapper carries what a written item carries for the same content: `li_itemize`/`li_enumerate not_number`, the `block` class when it holds block markup, the `data-custom-marker`/`data-marker-empty` pair the nested-list wrapper already uses, and line numbering, its `map` spanning what it wraps. Inside `<ol>` it takes the custom-marker shape (`not_number`, `display: block`) — a plain `<li>` there is counted by the browser, which moved every number below it by one.
    - It is applied **after** the chunk's tokens are emitted, so a run that emitted nothing is not wrapped and an empty chunk or a no-output command needs no test of its content. Deciding in advance meant predicting emission from the text, and each new shape needed another predicate. The one content test left is on tokens: a run of whitespace-only text tokens is not content.
    - All three emission points are covered — the block and inline paths in `ListItems`, and the same-line content in `ListOpen`, where only the run before the first `\item` is wrapped. The third is not redundant: `\begin{itemize} loose \item x \end{itemize}` emits its chunk there and nowhere else.
    - The token is built through `state.Token`, so the inline path's synthetic state carries the constructor a real `StateBlock` has; without it the constructor throws, the rule catches, and a list inside a paragraph or a table cell drops to literal LaTeX with one `console.warn`. That warning is the only trace, so the tests assert its absence alongside the HTML.
    - A sublist written in the chunk goes **inside** the wrapper — beside it, the `<ul>` is a direct child of a `<ul>`, the half of this shape `master` leaves broken along with the bare text. The same-line path takes a balanced open…close pair into the run; the block path emits chunk and sublist separately, so a pass over the finished list moves the wrapper's close past a sublist that follows it, on tokens rather than HTML, the cell exports walking those.
    - A chunk *between* two lists belongs to neither and takes no `<li>`, or it would land outside any list.

18. **A command written in an argument is text, for every reader.** One rule, applied where a reader decides structure: `maskNonStructure` hides code spans and `\item[…]` markers before the walk looks, `renewCommandSpanEnd` measures a `\renewcommand` so its body is skipped whole, and both scanners plus `unclosedEnvsIn` read the same masked text. What this reached: an `\end{itemize}` beside a code span used to be read as text along with the span and then closed a second list from inside item content, leaving a stray `</ul>`; a list command in a marker cost the whole list; `\renewcommand*`, `{\x}[1][d]{…}` and a bare `\name` were unmeasured, so the closer sharing their line was swallowed. A span that cannot be measured at all (unclosed brace) goes to the walk instead, keeping its `<br>` — losing the closer is the worse trade.

    - The marker body is parsed with the block flag still set on `env`, so a list written there opened a real one inside `<span class="li_level">`. All three marker parses are guarded by a counted flag, and `\item` with no list open stays text rather than emitting an `<li>` that has nothing to sit in — which also fixes two shapes that were pinned as quirks.
    - Not covered: `writtenAsText` pairs `{}` only, so the closer sweeps still count one written in an `\item[…]`. Over ten shapes built to reach it — a closer written only in a marker, at two nesting levels, before a sibling, inside a wrapper — the over-count changes no rendered document; the counters are a conservative bound by design. Teaching `pairArgumentSpans` about `[]` touches the source of truth every scanner reads, so it stays a boundary.

## Breaking change / migration

The canonical list is `doc/changelog.md` under **Breaking changes** — sixteen entries, each with what a consumer must do. Twelve more sit under **Fixes that change existing output**: they replace output that was broken or invalid, so a consumer diffing HTML sees them but has nothing to change. Migration, in the order it bites: readers of `data-padding-inline-start` must parse an em value with its unit; anyone reading a `tsv`/`csv` cell as an address must stop — a link contributes its href and the rest of the cell follows it, space-separated (`[a](http://u) tail` → `http://u tail`); anyone importing `lib/styles/styles-code` alone must also emit `MathpixStyle` for code text to keep its size; a TOC copied into a container other than `#toc_container` needs its own `padding: 0`.

## Testing

Rendered output is locked by full-HTML fixtures — 288 in `_data/_lists`, thirteen more in `_data/_lists/_data_known_quirks.js`, plus the caption, section and footnote sets — so a visual regression fails a fixture rather than passing quietly. Every shape named in this document is among them, including the ones that stay broken and the controls that must not break with them.

What is checked as an invariant rather than by example, because an example would pass while the rule was broken:

- **Every direct child of every list element is an `<li>`**, swept over all list fixtures — reading only the first child passed while an invalid `<ul>` sat second. The sweep bounds the fixtures, not every input, but no fixture and no quirk carries an unbalanced tag any more: a closer or an `\item` with no list open stays text instead of emitting one, which is what those shapes used to leave behind. A differential fuzzer was run against `master` and the branch point while this was written; it is not in the repository, so no count from it is quoted here.
- **Argument spans come back ascending, disjoint and landing on real braces**, over twenty thousand random brace strings, half of them with a verbatim range. The search over them is a binary one, so a nested pair leaking in makes a brace inside an argument read as one that opens a new argument. Asked of `md-latex-lists-env/list-source-model`, which holds what the rule knows about its source — the four readers of "is this closer structural?" live there together, and the test reaches the pairing directly instead of through a render.
- **`isInsideRanges` agrees with a linear scan at every offset** of twelve verbatim shapes; inline code opening before a fence and closing after it broke both that and the ascending order.
- **Repeated units parse linearly** — list units, unclosed `tabular`, a run of unmatched `{`, and a line full of closers written in code — each with a growth bound rather than a wall-clock threshold.
- **A leaf run in a table cell costs a constant number of renders per token**, so a rewrite that re-renders the run per member fails.
- **The guard table pins the exact item count `master` renders per shape**; a `> 0` assertion had passed while an item was lost.

Two invariants were checked by mutation rather than trusted, each by an early `return` at the function's entry — the count depends on that form, so it is named: neutralising `restoreEnvAll` fails 11 tests, neutralising `restoreEnvKeysFromAll` fails 8.
