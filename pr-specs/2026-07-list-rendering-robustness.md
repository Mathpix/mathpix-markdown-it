# PR: List rendering robustness fixes

Status: Implemented
Owner: @OlgaRedozubova
Base: master
Version: 3.1.0

---

## Context

Several unrelated inputs made LaTeX `itemize`/`enumerate` lists render incorrectly. The fixes touch the list-env, tabular and footnote block rules, the marker-width helpers (`common/display-width.ts`), and the marker-padding CSS. They ship together.

## Goal

Fix the reported list defects — clipped markers, empty `<>` item bodies, shifted `Figure N`, a swallowed list after a paragraph, content dropped from the tabular-cell export — without changing HTML for input that already rendered correctly. Marker indent must scale with the container `font-size`, and malformed input must not degrade quadratically.

## Non-Goals

- **Text between `\begin{itemize}` and the first `\item` stays inside the list, not before it.**
  - LaTeX rejects text there (`Something's wrong--perhaps a missing \item`), so there is no item to attach it to. Keeping it visible is deliberate; moving it out to a sibling before the list is not attempted.
  - It is no longer a direct child of the `<ul>` — fix 17 gives it a marker-less `<li>`. `\itemsep`/`\itemindent` arrive whole there rather than split into an item (fix 6), and stay visible: unsupported commands are shown, not swallowed.
  - A `table`/`figure` float in that position is a different case and is fixed (12): LaTeX accepts a float before the first item, it contributing no horizontal material.
- **Text after the outermost closer on the same line is dropped**, as on `master`: `\end{itemize}\end{itemize} trailing` loses `trailing`, because the walk has already flushed its items when that tail arrives and a block rule cannot hand a line's remainder to the next rule.
- **Two cell-export quirks stay as they are.** A `|` inside math is exported as `\|`, and a table parser does not unescape it inside the math (measured: the content reads back as `a\|b`), so the LaTeX changes meaning — unavoidable in this format, since an unescaped `|` would split the cell. A list exported from a cell ends with a `<br>`, because the separator closes every item: `| 1. a<br>2. b<br> |`. Both are pinned by fixtures.
- **Diagnostics go to the global `console`, and a degraded render leaves no programmatic signal.** A failing list rule warns once per cause per render and does not apply, so the caller gets HTML instead of an exception but cannot tell from the return value that anything was skipped. There is no channel for it: `ParseErrorList` (`md-block-rule/parse-error.ts`) is written by the tabular path and never read or exported, and `ParserErrors` is an enum of display modes for math errors. Both a public diagnostics surface and an injectable logger are library-wide API changes (117 `console` calls across 44 files, against 118 on `master`), left to one change of their own.
- **Malformed input with no blank lines is still super-linear**, whichever env is unclosed: every terminator probe is now cheap, but `newTheoremBlock` and markdown-it's `lheading` still scan forward from each block start without terminating, running the whole terminator chain per line. At 400 units that is 9.2M block-rule calls against 23k with those two disabled — the same input, linear. Each is quadratic on its own, so disabling one does not help; neither is touched here, and the shape reaches them with no list involved. A blank line between blocks avoids it.
- **Four wrapper shapes stay as they are.** Each is measured identical to `master` unless noted, so none is a regression.
  - *A spaced `\begin {center}`* builds no wrapper, the shared open regex admitting no space there. The list itself renders whole — two items, nothing leaked. Widening a constant shared with other rules is a change of its own.
  - *A wrapper inside a `tabular` cell* loses the table: `\begin{tabular}{l}\begin{center} x \end{center} \\\end{tabular}` between two items renders the cell content as a bare `center` div, on one line or three. This branch at least keeps both items, where `master` prints the whole list as literal LaTeX for the one-line form. `pdflatex` rejects the input too (`Not allowed in LR mode` — a `center` needs a `p{}` column or a `\parbox`), so it ranks below the valid shapes, and restoring the frame belongs to how cells are parsed.
  - *A fenced code block between a wrapper's `\begin` and its closer* makes the guard decline, the closer sweep being fence-blind: that shape renders as on `master` — three items, the wrapper as text — where the same one without the fence gets two items and its wrapper. Counting fences in pairs would separate a closer inside a closed block from one after it.
  - *A single-line nested `tabular` inside a `tabular` cell* leaves the opaque stack open, the nested-tabular branch returning before the same-line close: `x & \begin{tabular}{l}y\end{tabular} \\` in a list body prints the list as literal LaTeX. Two places decide "did it close on this line" and only one was taught to.
- **A wrapper nested inside another of the same name loses both frames.** The opaque stack pops on the first `\end{X}` with no depth count per name, so `\begin{center} outer \begin{center} inner \end{center} tail \end{center}` inside a list keeps the list and one centred block, while the inner opener and the outer closer come out as text. Valid LaTeX, measured identical to `master`, and pinned by a test so a depth counter added later reads as a deliberate change; `tabular` has such a counter in its own branch, which is where the pattern would come from.
- **The sweep caches hold up to eight sources per key on the `env` the consumer passes.** The key is the source string itself, so an `env` reused across renders — a pattern the tests treat as supported — keeps those strings alive until it is dropped. Eleven symbol keys exist today, and the cap bounds each; keying by something cheaper than the source, or clearing the buckets from the reset hook, is a change of its own.
- **The speculative-parse isolation has boundaries, documented where they live in the code.** Two are visible to a consumer: the `env` rollback compares values by identity, so a key whose object a rule mutated in place is left as the parse left it (`common/env-transient.ts`); and it diffs the whole `env`, so its cost follows the size of the object the consumer passes — 62 ms against 164 ms with 1000 extra keys on the same 200 units. The rest are internal: which module-global registries are restored and why the others are not, and why the inline registry pops by token kind while the block path pops by identity.

## Current Behavior

Marker width is `String.length` over `text` tokens, so wide, math and wrapped markers are undercounted and clip; padding is `px` and only on the outermost list. A speculative list parse leaks `env` flags and caption counters. `\footnote` scans swallow a following list. Inline content sitting directly in a `\begin{tabular}` cell never reaches `table-markdown`/`tsv`/`csv`. `\itemsep` is mistaken for `\item`.

## Desired Behavior

1. **Block-content items get marker padding.** Marker width was measured on the inline item path only, so a list whose long-marker items all hold a block env (`\begin{figure}`, `\begin{tabular}`, a code fence) lost its `padding-inline-start`. The width calc is now shared and applied on the block path too.
2. **Marker width accounts for wide/math/wrapped content.** Was `String.length` over `text` tokens only: East-Asian Wide/Fullwidth (`\item[11．]`), math (`\item[$x^4+x^4$]`, via rendered `widthEx`) and wrapped markers (`\item[\textbf{…}]`, via their children) are now measured instead of undercounted.

   What the estimate does not promise, by design: it reserves per glyph *class* against a Helvetica/Arial-like font, not per exact glyph, so a non-ASCII glyph can be off within a bounded margin; the Wide set is a fixed snapshot of Unicode, so a code point a later version declares Wide under-reserves by 25% until it is added (a build-time Unicode table was rejected for an estimate that is approximate anyway); math is measured only under SVG output, since `widthEx` is filled there alone — reading the LaTeX source instead tracks rendered width in the wrong direction (`$\displaystyle\sum_{i=1}^{n}$` is ~28 characters against ~3em); an image marker reserves by its alt text; and the em arithmetic assumes one `font-size` down the chain plus the shipped stylesheet's `2.5em` per ancestor, so a per-level size or a consumer rendering without that stylesheet shifts the reserve by the ratio. Above the `20em` clamp, and for a textless item followed by a wider-marker sublist, markers can overlap — the latter reproduces LaTeX.
3. **No state leak from a speculative list parse.** The rule parses into a buffered state before committing; a silent probe or abort discards the tokens.

   Transient `env` flags are restored on **every** exit, commit included — a leaked `isBlock` produced empty `<>` items on the next block. Everything else goes back only when the tokens are discarded: every `env` key the parse changed or added, diffed against a snapshot so a rule the list code never heard of is covered too; the module-global figure/table counters (a figure in a list is `Figure 1`, was `Figure 3`); and the list-level stack, pushed and popped so no half-open level closes an extra `<li>` later.

   A rule that throws does not apply — it answers "no list" and warns once per cause per render. Both paths guard themselves: the block rule for markdown-it's paragraph chain and `lheading`, the inline rule for its own call into the same engine, so whether the environment sits on its own line no longer decides between a rendered document and a failed one. Only a failure past the commit point propagates, its tokens being already in the stream; the levels and counters unwind either way.
4. **Footnote scans stop at a list start.** `\footnote`/`\footnotetext` now terminate their forward scan at `\begin{itemize|enumerate}`, so a list right after a paragraph (no blank line) is no longer swallowed as literal text. An unclosed env short-circuits twice: before parsing when the source holds no closer at all, and during the body walk when the closers left ahead are fewer than the envs already open. Probe answers are deliberately **not** memoized — with those two checks in place a memo measured slower on every shape, and its key would have to enumerate every input the answer depends on to stay correct. The second check is what covers a document that does end with a valid list — the sweep over-counts closers (one inside a fence is not real), so it can only keep the walk going, never cut a list that would have closed. Input that interleaves real closers with unclosed envs is only improved, not fixed: the closers ahead outnumber the open envs, so the walk continues even though none of them will close it (measured `N^1.7` with every tenth unit closed and `N^1.9` with every other one, against `N^2.0` on `master`).
5. **Marker padding in `em`, not `px`.** The indent and the `0.625em` marker gap now scale with the container `font-size`. A custom `padding-inline-start` is emitted only when the marker overflows the default (`2.5em`), attributed per nesting level and clamped at `20em`; the attribute carries its unit (`"4.23em"`).
6. **`\item` detection requires a real command.** `\itemsep`/`\itemindent` and the bare word "item" no longer split an item or break a multiline `\footnote` inside one; item detection anchors on `\item` + a command boundary.
7. **Markdown lists indent `2.5em`, not the UA `40px`.** Core-markdown `<ul>`/`<ol>` (no `.itemize`/`.enumerate`) get a scoped `#preview-content`/`#setText` rule that scales with the container; the numbered footnotes list is covered. Wrapped output only. `2.5em` equals the UA default only at a 16px base, and `PreviewStyle` sets `#preview { font-size: 17px }`, so in the shipped wrapper such a list sits at `42.5px` per level.

   A TOC under `#toc_container` or `.table-of-contents` is zeroed twice — this rule set at specificity `(2,0,1)`, and `padding: 0` from `TocStyle` later in order. A TOC copied into any other container matches no TOC rule at all, because `TocStyle` applies its parameter to the outer selectors only and hardcodes the inner ones; that shifts such a list by `2.5px` per level. Left alone deliberately: pairing every inner selector with the caller's name would also drop `list-style`, item padding, title sizes and link colours onto containers that never had them. The workaround is in the changelog.
8. **Inline content in a tabular cell reaches the export.** Content sitting directly in a `\begin{tabular}` cell was rendered to HTML only, its `table-markdown`/`tsv`/`csv` text dropped: measured, a link swallowed the rest of its cell (`[a](http://u) tail` exported as `| [a](http://u) |`) and a single-line nested list lost its sublist bodies (`| • a&#160;&#160;– <br> |`, the `b` gone). Both reach those exports now; HTML is unchanged. A flat one-line list was never affected — that shape exports the same on `master`.
9. **A link in a tabular cell keeps its label and closes its anchor.** Pre-existing and unrelated to lists, fixed here because it shares the cell-export path: the link consumed two tokens too many (open `<a>`, following content absorbed), and read its label from one token, so a formatted label came out empty.

    - The label is read whole, with every character that could end or re-cut it escaped in text and raw markup: `]` closes it, `[` re-pairs with that bracket, `\` escapes what follows.
    - Math and an image alt pass through verbatim, both being source slices that carry their own escapes (`image.ts` never parses the alt). Math takes the cell delimiters, `$…$` by default for display math too, since a backslash added there would change the LaTeX — `\\` is a line break. Those delimiters are also what shields an unbalanced `]` inside math for a reader that has a math rule.
    - An href a bare destination cannot hold takes the `<…>` form, and the pptx-smoothed output no longer carries a bare `<a>` or the raw HTML of a table written inside a label.
    - What the export cannot restore is an escape the parser already consumed: `[a\*b\*c]` reaches us as the text `a*b*c` (markdown-it's `escape` rule appends to the pending buffer, leaving no token to read), so it exports unescaped, as on `master`.
10. **Unclosed `\begin{tabular}` short-circuits.** Like fix 4, `BeginTabular` checks for a closing `\end{tabular}` before scanning to EOF instead of rejecting only afterwards, which cuts the cost of such a document by ~30×. Not list-related; included because the same probe-per-line pattern reaches it from the same malformed input.
11. **A line can carry several env transitions**, and all of them are handled, in source order. Before, one transition per line was handled and the rest became item text — where `ItemsAddToPrev` drops a pure closer — so the outer list never closed and the strict no-partial-tokens bail dropped it as literal text.

    - A collapsed `\end{itemize}\end{itemize}` closes two levels; a closer mid-line can open a sibling list rather than only a nested one; a second sublist on one line is no longer lost. The only change on already-correct output is a whitespace-only text node between `<ul>` and `<li>` that no longer appears.
    - A sibling opens only when the closers ahead cover what its tail leaves open — counted, not merely looked for, so a tail opening two levels needs two: an unclosed sibling aborts the rule and would take the finished list with it. Closers past the next fence opener do not count, the sweep being fence-blind.
    - The sibling reports its own depth: `parentType` is put back once the outermost list closes, or it would read as nested and lose one default indent.
    - Text before a transition opens its own item when it carries a marker, as it already did before a wrapper `\begin`. Appended to the item above instead, `\item b \end{itemize}` landed in a chunk that also held a block env, where only the first marker is read and this one printed as literal text; `pdflatex` renders that input, so the second item is owed.
    - Termination is by construction: every match consumes at least `\end{itemize}`, so the tail strictly shrinks.
12. **A block env in a list body reaches the block rules wherever it sits.** `finalizeListItems` block-parses an item only when its content holds a block env **and** an `\item`, so a chunk carrying one but no marker — the env following a closed nested list, or preceding the first item — fell to the inline path: `\begin{table}` leaked as text, `\captionsetup` left a stray `}`, and the caption was dropped. Such a chunk is now block-parsed into the already-open item, no new item token, gated by the same `LATEX_BLOCK_ENV_OPEN_RE` as the marker case — the two paths agree by construction. Measured: `table`, `figure`, `center`, `left` and `right` lost their wrapper in both markerless positions, and a `tabular` there rendered without the `table_tabular` wrapper it has at top level *and* after an `\item`, so those two positions were the odd ones out; one fixture pinned that, and it is updated. Backtick and tilde fences stay on the inline path — they are matched by the neighbouring conditions, not by this regex, and block-parsing them printed the backticks and lost the code. Both shapes are valid input — `pdflatex` accepts them with no warning — so this is a correctness fix, not tolerance for malformed LaTeX. 
13. **A wrapper env is opaque to the list scanner.** The body walk reads `\item` and `\end{itemize}` textually, with no notion of being inside a command argument, so a list command written inside a `table`/`figure`/`center`/`left`/`right` was taken as structure. Measured, with two items expected: `\caption{\item[a]}` gave **no items at all** (the bogus marker consumed the list), a stray `\end{itemize}` in a caption closed the list after one, and an `\item` inside `\begin{center}` produced three. Those five envs now join `tabular` and `lstlisting` on the opaque stack — their lines are collected raw until their own closer, so the interior is text and the block parse builds the wrapper from it. A nested `\end{tabular}` inside a `table` is content, not a closer, because the stack top picks its own pattern. The input is invalid LaTeX (`pdflatex`: `Argument of \caption@ydblarg has an extra }`, no PDF), so the aim is well-formed degradation, not fidelity — the command stays visible as caption text.

    A wrapper turns opaque only when its `\end` is ahead and reachable — otherwise the stack never pops and the rest of the list, which renders today, is collected as raw text. Each condition below cost a measured shape before it was added, and every decline path equals the previous behaviour by construction, which is why a mutation of this code does not fail there.

    - **Ahead of the `\begin` itself, not of its line.** An `\end{X}` written left of the opener — dangling, or already consumed by an earlier wrapper on that line — read as reachable: three shapes lost the whole list where `master` renders two items.
    - **Order, not a tally.** With one closer and one opener in the window the counts balance, yet a closer standing first is still ours: tallying them cost item `b` of `\begin{itemize}\item a \begin{center} \end{itemize} \begin{itemize}\item b \end{center}\end{itemize}`. One merge walk over the two ascending offset lists answers it and stops at that closer.
    - **A closer inside a command argument is text.** `\item b \end{itemize}` ends the list; `\caption{x \end{itemize} y}` does not. Counting line-initial commands instead was wrong in both directions — it kept the `\caption{}` shape but printed three others as literal LaTeX, `\item b \end{itemize}` among them.
    - **Argument spans come from `findEndMarker`**, the helper the caption and text rules already use, so escaped braces and inline code are its business rather than a second copy here. The code-span index is computed once per window and passed in: building it per call put that helper at 21% of a parse on a document of unclosed wrappers.
    - **The window is bounded at 4096 characters.** An unclosed wrapper reaches the document's end, and parsing that per wrapper is quadratic; past the bound a closer reads as unmatched, which declines.
    - **An unmatched `{` makes the spans unknowable**, and then every closer counts — `master`'s behaviour for those shapes. Trusting depth instead printed the whole list as LaTeX for an unclosed `\caption{x`, a bare `{`, and `$\frac{1}{2$`, the last ordinary in OCR output.
    - **A closer inside a code fence does not count.** Over-declining is the safe side; the limits this leaves are in Non-Goals.
    - **One source of truth for the names.** The wrapper names, their closer patterns and their cache keys derive from one list in `consts.ts`, and the guard looks for the first *wrapper* on a line rather than the first block env — asking for the latter left the answer to where `tabular` sits among those names.

    A wrapper that opens **and** closes on one line is read on that line: pushing the opaque stack and handing the whole remainder to the item left the stack open for good, and the strict bail printed the list as LaTeX. Measured against `master`, the one shape this changes for a consumer is a single-line `\begin{tabular}{l}q\end{tabular}` in a list body, which `master` drops the whole list for; the five env wrappers reached the opaque stack only in this branch (fix 13), so their one-line form was broken and fixed inside it and comes out as on `master`. The tail after the closer goes back to the line walk, so a marker or a closer following it is read normally.

14. **A list inside a wrapper env keeps its nesting depth.** Wrapper content is collected raw and reaches the block rules from the *inline* phase, on a synthetic state that cannot see the enclosing list — so a list parsed there claims top level. The renderer reset its depth on that claim, which gave the nested list a level-1 marker and left the counter negative for the item after it. Measured, against `•  –  •` without a wrapper: any of the five wrappers between two `itemize` levels gave `•  •  •`, and for `enumerate`, where the marker is the list style, `decimal | decimal` instead of `decimal | lower-alpha`. Both branches now reset only when no list is open, and the per-render reset — depths and enumerate counters together — lives in one place, called from `reset_mmd_global_state`. The reset is load-bearing drift recovery, not decoration: gating it without that per-render call fails 8 tests.

15. **Two caches that were not caching.** Both costs are pre-existing; this branch made them visible by multiplying them.

    - **Marker macros.** Every list open re-parsed `\textbullet`, `\textendash`, `\textasteriskcentered`, `\textperiodcentered` through the inline parser — 12 to 16 times per list block, about 250 of the ~310 inline characters a block spends. Parsed once per macro per parse now, cached on `env` and keyed by the macro, so a `\renewcommand` mid-document still switches markers.
    - The bucket is dropped when the md instance or its `outMath` changes, `env` being the consumer's and able to reach two of either. `forDocx` keeps its own uncached tokens, parsing with a mutated `outMath` and no math cache.
    - Each read hands back a copy of the array, which keeps a consumer's damage inside its own list: a rule clearing the array it was handed poisons every later list without the copy and only its own with it. The tokens stay shared, so writing to one still leaks — freezing them was tried and rejected, the library writing to none but a consumer's strict-mode renderer then throwing. The copy costs nothing measurable in time (its sign flips between runs of a same-process A/B) and ~0.7% of peak heap.
    - **Source sweeps.** The cache lived on the state object, while block rules ask through a buffered probe (`Object.create(state)`) whose own properties die with it, so the sweep reran per probe: 200 units with a wrapper in every list ran 1001 sweeps over the full source, 18.1 M characters, where 6 suffice. It is hosted on `env` now, which the probe inherits by reference, one entry per `src`.
    - Eviction is by age with a hit refreshing its slot. Dropping the oldest alone threw out the outer document's entry — the one asked over and over — once nine nested sources had passed, and its sweep count then grew with the wrapper count (5, 6, 8, 13 over 10 to 80 wrappers) instead of staying at 4.

16. **`findEndMarker` reads an escape by parity, not by the previous character.** The helper that pairs `{`/`}` for the caption and text rules treated any preceding `\` as a shield without asking whether that `\` was itself escaped, and `\\` is a line break in LaTeX. Measured: `{a\\}` reported no match where the `}` closes, `{a\\{b}` reported a match where nothing closes, and `{a\\{b}}` closed on the inner brace. End to end, `pdflatex` renders both of these and this library dropped them: `\caption{first line \\}` produced no caption at all, `\section{title \\}` no heading, and `\caption{a \\{b} c}` lost everything after the inner brace. Pre-existing on `master`, fixed here because the list guard pairs arguments through the same helper. Its optional `inlineCodePositions` parameter is new for that caller: the code-span index is rebuilt per call otherwise.

17. **A chunk before the first `\item` gets a marker-less `<li>`.** `<ul>` admits only `<li>`, and such a chunk went in beside them: text and an unsupported command as a text node, a fence or a block env as an element — `master` does the same with its own shapes.

    - The wrapper carries what a written item carries for the same content: `li_itemize`/`li_enumerate not_number`, the `block` class when it holds block markup, the `data-custom-marker`/`data-marker-empty` pair the nested-list wrapper already uses, and line numbering, its `map` spanning what it wraps. Inside `<ol>` it takes the custom-marker shape (`not_number`, `display: block`) — a plain `<li>` there is counted by the browser, which moved every number below it by one.
    - It is applied **after** the chunk's tokens are emitted, not before: a run that emitted nothing is not wrapped, so an empty chunk and a no-output command (`\renewcommand`, however many lines) need no test of their content. Deciding in advance meant predicting emission from the text, and each new shape needed another predicate. The one content test left is on tokens, not source: a run of whitespace-only text tokens is not content — the block path trims its chunk, the same-line path cannot.
    - All three emission points are covered — the block path and the inline path in `ListItems`, and the same-line content in `ListOpen`, where only the run before the first `\item` is wrapped. Missing the third left `\begin{itemize} loose \item x \end{itemize}` with a text node in the `<ul>` while the fixture sweep passed, no fixture using that form.
    - The token is built through `state.Token`, which the synthetic state of the inline path did not carry: the constructor threw, the rule caught it, and a list inside a paragraph or a markdown table cell dropped to literal LaTeX with one `console.warn`. That state now carries the constructor a real `StateBlock` has, and the tests assert the absence of the warning as well as the HTML — the warning was the only trace.
    - A chunk *between* two lists belongs to neither and takes no `<li>`, or it would land outside any list.
    - Fixtures cover every shape the chunk can take — text, block env, one-line form, whitespace, `\renewcommand`, `enumerate`, nested list, and a list with no `\item` at all — and a sweep asserts across all list fixtures that the first tag after each `<ul>`/`<ol>` is an `<li>`.

## Breaking change / migration

The canonical list is `doc/changelog.md` under **Breaking changes** — fifteen entries, each with what a consumer must do. Migration, in the order it bites: readers of `data-padding-inline-start` must parse an em value with its unit; anyone importing `lib/styles/styles-code` alone must also emit `MathpixStyle` for code text to keep its size; a TOC copied into a container other than `#toc_container` needs its own `padding: 0`.

## Testing

Rendered HTML is locked by full-HTML fixtures, so a visual regression fails a fixture rather than passing quietly.

- `_data/_lists` — every shape a chunk before the first `\item` can take (text, block env, one-line form, whitespace, `\renewcommand`, `enumerate`, nested, a list with no item at all, and the one-line form on the inline path: inside a paragraph and in a markdown table cell); marker padding per class; B2 nesting in every written form; collapsed closers and sibling lists, including the two shapes where the sibling guard must decline; a block env after a nested list, in the list fixtures and the tabular ones; a list command inside a wrapper env; each wrapper opening and closing on one line; a closer ending its line, with a foreign env after it, with a lone `\end{center}` below, and with neither; a marker before such a closer; crossed env boundaries with equal counts in the window; an unmatched `{` in a wrapper; empty-`<>`; `\item` detection; footnote terminators.
- `_data/_captions` — numbering not shifted by a speculative parse; a caption ending in `\\`, and one holding `\\{b}`.
- `_data/_sections` — a heading ending in `\\`. `_data/_footnotes_latex` — a `\footnotetext` mentioning "item".

Behaviour that no fixture can express stays as targeted assertions.

- `_lists.js` — what counts as `\item`; no orphan `<br>` from a swallowed command; the guard table pinning the exact item count `master` renders per shape, a `> 0` assertion having passed while an item was lost; marker depth through each of the five wrappers, for `itemize` and `enumerate`; markers following a `\renewcommand` that switches them mid-document and back; a math marker coming out alike in every list and again on the next render; one `env` shared by two md instances keeping their markers apart; a same-name nested wrapper pinned as measured; a sweep asserting every list element in the fixtures holds nothing but `<li>`.
- `_src-pos-cache.js` — the two boundary searches; a sweep run inside a buffered probe reused afterwards; entries for different sources coexisting; the outer document's entry surviving more nested sources than the cap.
- `_find-end-marker.js` — twelve brace shapes over the parity rule, the four that changed and the controls that must not; a brace inside inline code; the passed-in code index.
- `_parse-isolation.js` — a silent probe leaving `env` unchanged over 21 list bodies; the snapshot pool; the identity boundary of the rollback; a failing rule not failing the document on either path; diagnostics reset per render; render depth reset before the partial-render bail, checked by forcing drift through a no-op close rule.
- `_footnotes_latex.js` — repeated units parsing linearly, with and without a valid list after them; the unclosed-`tabular` growth bound beside the `itemize` one.
